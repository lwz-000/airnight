# AIRNIGHT 特效图制作规格书

> **给做图的人（+ 帮你的 AI）看的。你不需要写任何代码** —— 只要按这份规格交图，
> 这边负责接进游戏里。
>
> 游戏是《AIRNIGHT》（明日方舟主题的网页自走棋，3D 棋盘 + 2D 棋子），特效全部是 **2D 图片**，
> 贴在棋盘上或挂在棋子身上播。这份文档分三块：
> **① 交什么格式**（第 1~3 节） · **② 每类特效在游戏里长什么样**（第 4~7 节） · **③ 怎么用 AI 出图**（第 8~10 节）。

---

## 1. 一句话说明"特效在游戏里是怎么播的"

战斗是全自动的（棋子自己走过去打），**特效的触发时机是固定的**：

| 什么时候 | 播什么 | 大概多长 |
|---|---|---|
| 每次普通攻击打到人 | 命中特效（挥砍弧 / 命中爆点） | 0.15~0.3 秒 |
| 放技能的那一刻 | 技能特效（起手 + 持续/命中） | 0.3~0.6 秒（持续类会循环） |
| 技能持续期间 | 身上/脚下的循环光效 | 一直循环到技能结束 |
| 被打/回血/加盾/被控 | 状态特效 | 0.2~1 秒或持续 |

棋盘是**俯视 45°**看的（不是正上方、也不是正面）——这一点决定了很多画法（见第 4 节）。

## 2. 交付格式（硬性要求，照做就能直接用）

### 2.1 文件格式

- **PNG，32 位（RGBA，带透明通道）**，8 位/通道。
- **不要 JPEG**（没有透明通道，还会有压缩噪点）。不要 WebP/GIF。不要 PSD（可以另附，但要给导出的 PNG）。
- 单张图 **不要超过 2 MB**；序列帧整张 **不要超过 4 MB**。

### 2.2 序列帧的排法（**横向排**，和游戏里现有的小人素材一模一样）

```
┌────┬────┬────┬────┬────┐
│ 1  │ 2  │ 3  │ 4  │ 5  │   ← 一张 PNG，从左到右
└────┴────┴────┴────┴────┘
```

- 一张 PNG = 一个动作 = N 帧，**每帧等宽等高**。
- 整张 PNG 的尺寸 = `帧宽 × N` 宽、`帧高` 高。
  （例：每帧 256×256、8 帧 ⇒ PNG 是 2048×256）

### 2.3 每帧画布尺寸

| 类型 | 每帧建议尺寸 | 说明 |
|---|---|---|
| 命中火花 / 爆点 / 小额光效 | **128×128** | 小、快、亮 |
| 普攻弧、单格光环、护盾罩 | **256×256** | 最常用 |
| 范围技能（3×3、5×5）、大爆炸 | **512×512** | 要盖住 3~5 格 |
| 直线/长条技能（如"前方 3 格"） | **768×256** | 横向长条 |

**尺寸的换算基准（很重要）**：

> **游戏里 1 格 = 建议按 256 px 设计**（现有素材实测约 249 px/格，取 256 好算）。
> 也就是说：**"周围 1 格"（3×3）的圈 ≈ 768 px 直径**、"5×5"≈ 1280 px。

不用怕画得比"实际显示"大 —— 游戏会按格子把它缩放到正确大小，**画得越大越清晰**（上限 2048）。
**怕的是画小了**（放大就糊）。

### 2.4 对齐（锚点）

- **默认：贴地类/居中类特效，画布中心 = 落点。** 四边留 4~8 px 透明边（防止被裁切）。
- **方向性特效（直线/锥形/冲击波）**：约定 **默认朝右（+X 方向）**，
  起点放在**画布左侧中点**；游戏会按"施法者 → 目标"的方自动旋转，
  向左时会**水平翻转**（注意：所以**不要在图里写文字/数字/不对称的字母**，翻转后会反）。
- 每张图请在 `anchor` 里写清楚（见 2.6）。

### 2.5 目录与命名（全 ASCII，别用中文/空格）

```
特效图/
  <特效率id>/
    main.png          ← 主序列帧（横向）
    loop.png          ← （可选）持续期间循环的那套
    manifest.json     ← 元数据
```

- **id 用小写英文 + 下划线**，例如 `chen_slash`、`fx_impact_light`、`tianhuo_meteor`。
- 一个特效有多套动作时（起手 / 持续 / 命中），**拆成多个 id 或加后缀**（`_cast` / `_loop` / `_hit`）。
- 如果只是**单张静态图**（不动的），直接给 `<id>.png` + 一行说明即可。

### 2.6 `manifest.json`（照抄这个模板改）

```json
{
  "id": "fx_impact_light",
  "name": "轻击命中火花",
  "description": "近战普攻打中目标时，在目标身上闪一下",
  "anchor": "center",
  "cell": { "w": 128, "h": 128 },
  "animations": {
    "main": { "file": "main.png", "frames": 6, "fps": 24, "loop": false }
  },
  "usage": "普攻命中（近战/轻）",
  "notes": "外缘渐隐到全透明；主体明亮，游戏用加色混合"
}
```

| 字段 | 含义 |
|---|---|
| `anchor` | `center`（中心对齐） / `left-center`（左侧中点 = 起点，方向性特效用） |
| `cell` | **单帧**的宽高 |
| `animations[].frames` | 这张 PNG 里有几帧 |
| `animations[].fps` | 每秒播几帧 |
| `animations[].loop` | 循环吗（持续类 `true`，一次性 `false`） |

**帧数/帧率建议**（照着来就行）：

| 用途 | 帧数 | fps | 总时长 |
|---|---|---|---|
| 命中火花、爆点（一次性） | 4~8 | 24 | 0.17~0.33 s |
| 挥砍弧（一次性） | 6~10 | 30 | 0.2~0.33 s |
| 技能起手（一次性） | 8~12 | 24 | 0.33~0.5 s |
| 持续期间循环光效 | 12~16 | 12~16 | 1 圈 1 秒左右 |
| 大招收尾/爆炸 | 12~24 | 24~30 | 0.4~0.8 s |

## 3. 画法上的硬规矩（违反的话，成品在游戏里会很难看）

1. ★★ **背景必须完全透明**，而且**外缘要渐隐到 alpha = 0**。
   如果最外圈是"半透明的一块"，游戏里会看到一个**方框边缘**。
2. ★★ **主体要亮、要饱和**。游戏对发光特效用的是**加色混合**（把颜色加起来），这意味着：
   - 图上的**暗色会几乎看不见**（黑 = 什么都不加）；**黑色描边 = 完全没有描边**；
   - **接近白的颜色叠上去会发灰发雾**（看起来像蒙了层雾）——
     想要"金色"就用**饱和的金**（`#ffd058`~`#e0a828` 那一带），不要用 `#fffaf0` 这种近白色。
3. **不要烘焙地面、阴影、棋盘底纹、光晕底**——特效是贴上去的一层，底图会让它变成一块糊掉的东西。
4. **不要写文字/数字**（会被翻转；而且中文字体在这套素材里没有统一规范）。
5. **斜俯视**：贴地特效在游戏里是从 45° 斜上方看的 ⇒ **正圆会被压成椭圆**。
   要做"地面上的圈"时，请**按椭圆画**（或按扇形画），或者干脆告诉我们"这张要按俯视压扁"。
   挂在棋子身上的（非贴地）不受影响，按正视角画即可。
6. **统一光心**：亮的部分集中在中心或沿运动方向，别让整幅图都灰蒙蒙的看不清主体。
7. **序列帧的帧间一致性**：同一特效的所有帧**同画布、同锚点、只有主体在动**。
   （AI 出图最容易在这里翻车：每帧位置/大小漂移，连起来播会"抖"——对策见第 9 节。）
8. 颜色语义（游戏里已经定了，请沿用）：

| 含义 | 颜色 |
|---|---|
| 伤害 / 命中 | **白**（爆点、伤害数字） |
| 治疗 | **绿** |
| 我方单位 / 我方半场 | 蓝（半场底色是蓝的 ⇒ 贴地特效要用**提亮版**的蓝，别用原来的深蓝） |
| 敌方单位 / 敌方半场 | 红（同理，用提亮版的红） |
| 技能专属色 | 按干员设定（例：锏的斩击已经定为**深黄** `#ffe08a`/`#e0a828`/`#8a5c10`/刀锋近白 `#fff0be`） |

## 4. 各类特效的"战斗方式"与视觉模板（最重要的一节）

下面 8 个模板覆盖了目前游戏里全部的技能形态。**先看类别，再看第 6 节里你要做的具体干员属于哪一类。**

### 模板 A｜自身强化（最大的一类，数据表里 `→self`）

- **战斗方式**：干员放技能 → **自己身上/脚下**冒一圈起手光（0.3~0.5 秒，一次性）
  → 技能持续期间**身上挂一层循环光效**（10 秒里一直转）→ 技能结束时淡出。
- **要交两张图**：
  1. `xxx_cast`：起手（贴地一圈扩散的光环 + 少量上升粒子），一次性，256×256，8~12 帧；
  2. `xxx_loop`：持续（贴身的一层光/符文/气场），循环，256×256，12~16 帧。
- **注意**：循环那套要能**无缝首尾相接**（第 1 帧和第 N+1 帧视觉上连着）。

### 模板 B｜全队增益（`→allAllies`，例：阿米娅、可露希尔）

- **战斗方式**：从施法者脚下向外**扩散一个大环**（盖住全场），同时全队脚下各亮一下。
- 交一张贴地扩散环：512×512，8~10 帧，一次性。

### 模板 C｜单体指向伤害 / 控制（`→currentTarget` / `→lowestHpEnemy` / `→nearestEnemy`）

- **战斗方式**：施法者 → 目标之间**一道弹道或一道光束**（0.1~0.2 秒），命中处爆一下。
- 交两张：`_proj`（弹道，方向性，`anchor: left-center`，横向 256×64）+ `_hit`（命中爆点 256×256）。
  （也可以只交"命中"那一张，代码里用一条亮线连过去。）

### 模板 D｜直线（`shape: line`，例：陈的"前方 3 格"、左乐的"前方 2 格"）

- **战斗方式**：从**施法者脚下**朝目标方向**推出去一条长条刀气/冲击**，覆盖 2~3 格。
- 交一张：**768×256**（起点在左侧中点，朝右），一次性，8~12 帧。
- ★ 尺寸要**真的只盖住 3 格**（3 格 = 768 px）——这是一条"说几格就几格"的规则，
  画长了玩家会以为范围更大（游戏里的范围白框就是这么被报过 bug 的）。

### 模板 E｜范围伤害（3×3 / 5×5 / 溅射，例：天火、菲亚梅塔、聆音、隐德来希）

- **战斗方式**：目标位置或施法者周围**地面炸开一圈**（环向外扩 + 中心亮一下）。
- 交两张：`_ring`（贴地扩散环：3×3 用 512×512；5×5 用 1024×1024）+ `_core`（中心爆炸 256×256）。
- ★ 贴地环请**按椭圆画**（见第 3 节第 5 条）。

### 模板 F｜召唤 / 陷阱（例：迷迭香的战术柱、望的棋子）

- **战斗方式**：落点上一道光柱（0.2 秒）+ 落地的一圈尘（0.3 秒）。
- 交两张：`_beam`（竖直光柱，256×512）+ `_dust`（贴地小环，256×256）。

### 模板 G｜护盾（例：信仰搅拌机、机械师、左乐、新约能天使）

- **战斗方式**：护盾**获得时**炸一圈（0.3 秒）+ **存在期间**贴在棋子身上的一层半透明罩子
  （循环，12~16 帧）+ **被打碎时**碎一片。
- 罩子请画成**贴合棋子的弧形/椭圆罩**（棋子是 2D 小人，罩子会挂在他那一格上）。

### 模板 H｜治疗（例：古米、芙蓉、凯尔希、赤刃明霄陈）

- **战斗方式**：**绿色**（游戏里绿色 = 治疗）的上升粒子/光柱，落在被治疗的人身上。
- 交一张 `_heal`：256×256，8~12 帧，一次性可循环。

### 另外这些"通用特效"也很值得做（不绑定某个干员）

| 用途 | 说明 | 建议尺寸 |
|---|---|---|
| 普攻命中·轻 / 中 / 重 | 近战挥砍的弧（轻=匕首、中=剑、重=重锤），画在目标身上 | 256×256 |
| 远程命中爆点 | 箭矢/子弹打中的一点白光 + 短芒 | 128×128 |
| 野怪重击 | 更大的弧 + 一圈地面冲击环（野怪比干员"重"） | 512×512 |
| 眩晕 | 头顶转圈的小星星（循环 1 秒） | 128×128 |
| 闪避 / 免疫 / 未命中 | 现在游戏里**完全没有表现**：一层瞬时白光 + 一个"闪"的感觉 | 256×256 |
| 无敌 / 重生 | 角色身上金色光华流转（循环 16 帧，游戏里已有程序化版本，可以换成图） | 256×320 |
| 地面范围框 | 技能预览用的白框（方形 / 十字 / 直线 / 星形）——**要低对比、不遮棋子** | 见 §2.3 |
| 伤害数字 | 白字（暴击更大）——可选，做了会更"打得动" | 单字图集 |

## 5. 尺寸对照速查（把"格"换成 px）

| 游戏里说的 | 棋盘上的样子 | 建议画布 |
|---|---|---|
| 1 格 | 一个格子 | 256×256 |
| 周围 1 格 / 3×3 | 9 格 | 768×768（可缩到 512×512，但会略糊） |
| 周围 2 格 / 5×5 | 25 格 | 1280×1280（同上，建议 1024） |
| 前方 2 格（直线） | 2 格长条 | 512×256 |
| 前方 3 格（直线） | 3 格长条 | 768×256 |
| 整个人形棋子 | 小人 + 卡片 | 256×320 |

（一个棋子在画面上的可视高度 ≈ 244 px，"一格"的贴图 ≈ 249 px —— 上面是取整后的建议值。）

## 8. 用 AI 出图的实操建议（这部分很省时间）

### 8.1 通用提示词模板（英文对图像模型更稳）

```
game VFX sprite sheet for a top-down strategy game,
{效果描述}, {颜色},
centered composition, bright glowing core, outer edge fading to fully transparent,
solid black background, no ground, no shadows, no text, no watermark,
clean silhouette readable at small size, 8 frames in a horizontal row, evenly spaced
```

**把 {效果描述} 换成具体的东西**，例如：

- 轻击命中：`a small sharp impact spark, white flash with 4 short rays, minimal`
- 重击 / 野怪：`a heavy ground slam shockwave, wide bright arc plus an expanding ring, warm orange`
- 直线刀气（陈）：`a horizontal crescent blade slash pushing to the right, deep yellow gold, long thin trail`
- 治疗：`rising soft green healing motes, gentle vertical beam, soft glow`
- 护盾：`a translucent oval energy shield, cyan rim light, subtle hex pattern`
- 范围爆炸：`a ground explosion ring expanding outward, bright white core, orange ring`

**⚠️ 关于透明背景**（多数图像 AI 出不了真透明）：
让它出 **纯黑底**（`solid black background`），黑底对"加色混合"本来就是天然底色，
后期用任意工具把黑色转成透明（Photoshop 的"滤色/线性减淡"叠加到透明层，或图像编辑器里的
"黑色转 alpha"），再按 §7 检查外缘。

### 8.2 序列帧一致性（AI 最容易翻车的地方）

AI **逐帧独立出图 = 每帧都会飘**（大小、位置、形状都变），连起来播就是"抖"。
三个可行做法，按省事的顺序：

1. **出 1 张母图，再用图像编辑工具"改"出后续帧**（缩放/旋转/透明度/形变）——
   最稳，而且对"光效扩散/收缩"这类本来就适合变形。
2. **用图像 AI 的"局部重绘 / img2img + 固定 seed"**，只让主体的某个部分变化。
3. **用视频生成工具出一小段（1 秒）再拆帧**——动作连贯，缺点是分辨率和背景不好控。

### 8.3 交给我们的方式

- 交 **一个文件夹**（按 §2.5 的结构），或直接给**几张试做**先看风格。
- 每张图附一句"这是干什么用的"（比如"近战重击命中，贴地"）——我这边好接。
- 拿不准的，**先交 1~2 张样例**，我们会回一张"在游戏里的实际效果截图"，
  风格确认了再批量做，能省掉大量返工。

## 9. 附：为什么"程序化自绘"和"交图"两条路都行得通（给好奇的人）

现在游戏里的特效有两类实现：

- **程序化画的**（代码在运行时用几何/画布现画：普攻弧、范围白框、角色金色光华）——
  好处是零素材、零授权风险、随时能调参数；
- **图片素材**（现在的棋子小人就是这条路：`assets/chibi/<干员>/{idle,attack,skill,die}.png` + `manifest.json`）。

**你交的图走的就是第二条路** —— 和"小人"完全一样的格式，所以能直接用。
两种可以混着用：比如普攻弧继续用程序化，**技能特效全部换成你画的图**。

★ 另外提醒一句：**官方（鹰角）的立绘/小人/音乐不进仓库**，只能由使用者在本机按 `scripts/fetch-*.ts` 抓取；
含素材的完整包作为 Release 附件发布，并在权利人提出异议时 24 小时内下架（见根目录 `NOTICE.md` 第 5 节）。
你画的图是原创素材，交进来没有授权问题；但**不要把官方素材混在交付物里**。
