## 一、现在能跑什么

**最简单的办法：在项目文件夹里双击 `启动游戏.cmd`。**
它会自动打包、起服务器、起网页、打开浏览器 —— 一个窗口搞定，关掉窗口就全停。
需要联机自检就双击 `联机测试.cmd`，改完代码想跑全套检查就双击 `一键验证.cmd`。
（三个文件都放在项目根目录，细节看 `启动说明.txt`。）

> ⚠️ 这三个 `.cmd` 文件里的内容**必须全是 ASCII**。
> cmd.exe 是按当前代码页逐行解释 `.cmd` 的，文件里任何一个中文
> 都会被当成命令，直接报 `'??启动游戏' is not recognized...`（实测踩过）。
> 所以中文提示一律由 Node 输出，`.cmd` 只负责 `chcp 65001` + 调用 node。

命令行也可以用（在项目根目录 `E:\AIRNIGHT` 执行）：

```bash
# 一键启动（等价于双击「启动游戏.cmd」）
node scripts/pnpm.mjs launch

# 跑完整测试并检查数据表
node scripts/verify.mjs

# 看一场战斗的完整过程（带伤害统计和棋盘站位）
node scripts/pnpm.mjs sim -- --seed 123 --stats --board

# 连打 200 场统计胜率（调平衡用）
node scripts/pnpm.mjs sim -- --best-of 200 --quiet

# 平衡性诊断（全棋子对抗矩阵）
node scripts/pnpm.mjs balance
```

> **注意**：不要直接敲 `pnpm install`。你系统的 PowerShell 禁止运行脚本（执行策略限制），
> 会报「无法加载文件 pnpm.ps1」。用 `node scripts/pnpm.mjs <命令>` 代替，它用 node 直接调用 pnpm。

**游戏内操作**：左边选棋子 → 点场上的格子放下（只能放左半边）→ 回车开战。
右键撤回，空格暂停，右上角开关相机环绕。
**把滚轮往上滚可以拉近视角**（最近是默认距离的一半），拉近后按住棋盘空白处拖动可以平移；
顶栏那个「视角 ×1.0」徽标点一下回到最远。

### 和朋友联机的完整流程

1. 先启动服务器（`node scripts/pnpm.mjs server`）
2. 所有人打开 `http://<你的局域网IP>:5173` —— **不要用 localhost**，
   那样连的是朋友自己那台电脑的服务器，当然连不上
3. 一个人点「建房间」，把 6 位房间码念给其他人；其他人填码点「加入」
4. 除房主外的人点「准备好了」→ 房主点「开始游戏」
5. 每回合 60 秒布阵（**时间到自动开打，没有提交按钮了**）；
   布阵期间点右侧玩家列表里的头像可以看别人的棋盘

在自己电脑上试：**开两个浏览器标签页**就能当两个玩家。

## 二、已完成的部分

### ✅ 1. 确定性战斗内核（`packages/shared`）

这是整个项目技术难度最高的部分，已经完成并通过验证。

**「确定性」是什么意思？为什么它是联机的地基？**

自走棋的联机做法和普通网络游戏不一样：战斗不是实时对打的，而是
「服务器发一个随机种子 + 双方阵容 → 每台电脑各自算出完全一样的战斗过程 → 各自播动画」。

这样做的巨大好处：
- 战斗期间网络流量几乎为零（只传几百字节）
- 天然支持快进、录像回放、断线重连
- 服务器可以校验客户端有没有作弊（对一下校验和就知道）

**代价是：所有数值计算必须是整数，绝对不能出现小数。**
因为小数在不同 CPU 上的最后几位可能不一样，一场战斗算上千次就会累积成
「我这边赢了、朋友那边输了」—— 这是最难查的一类 bug。

所以内核里：
- 血量 550.5 存成 `550500`（千分之一为单位）
- 百分比 25% 存成 `2500`（万分之一为单位）
- 所有除法都用 `Math.floor` 向下取整
- 随机数用自己的发生器（种子化），**禁用 `Math.random()`**

**验证结果**：
- 19 个单元测试全部通过
- 同一颗种子跑 20 次，连事件日志的字节都完全相同
- 100 场随机阵容大规模测试无异常

**联机核心链路的实现方式**（这是整个项目最关键的设计）：

```
服务器：simulate(阵容A, 阵容B, seed)  →  算出胜者 + 校验和
   ↓ 广播（只有几百字节）
  { seed, 阵容A, 阵容B, 期望校验和 }
   ↓
客户端：simulate(阵容A, 阵容B, seed)  →  重放出完全一样的战斗，播动画
   ↓ 比对校验和
   一致 → 正常     不一致 → 上报服务器（说明确定性被破坏了）
```

好处：**战斗期间零实时同步压力**，不需要 rollback netcode；天然支持快进和录像回放；
服务器只做校验，一台最便宜的机器就能带 8 人房。

| **视角翻转**：被分到队伍 1 时自动左右镜像，棋子永远在自己左下角 | ✅ |
| **本地重放 + 校验和比对**：不一致会在控制台报错并自动上报服务器 | ✅ |
| 断线自动重连（断线后自动重连并恢复上次的建房/进房动作） | ✅ |

**「2D 人物」是怎么实现的？**
用 `Sprite`（永远面朝相机的平面）+ Canvas 程序化生成的卡片贴图。
卡片上的颜色、名字、费用、星级、特质全部来自 `unit-data.ts` ——
**你改数据表，画面立刻跟着变**。血条按 5% 分档缓存，不会因为每帧重画而掉帧。

以后换成真立绘只需改 `sprite-graphics.ts` 一个文件：
把绘制代码换成 `loadTexture(def.sprite + '.png')`，其他代码一行都不用动。

### ✅ 5. 客户端联机接入（`apps/web/src/net/`）

**已经实测打通。** 用 `node scripts/pnpm.mjs smoke` 可以看到完整链路：

```
服务器        0xEE719482  ✓ 一致
房主本地       0xEE719482  ✓ 一致
朋友本地       0xEE719482  ✓ 一致
```

三台机器（服务器 + 2 个客户端）用同一颗种子算出了完全相同的战斗。
实测流量对比：同步整条战斗过程要 40.1 KB，实际只广播「种子 + 阵容」0.73 KB —— **省了 55 倍**。

**「视角翻转」是这块最关键的难点，单独说明：**

真实坐标只有一个：队伍 0 永远在左半边（列 0..3），队伍 1 永远在右半边（列 4..7）。
服务器就是按这个坐标系算战斗的，**不能改**（改了就不是确定性推演了）。

但玩家永远希望「我的棋子在画面左下角」。所以：

- 服务器在自己的 `battleStart` 广播里带上 `team0PlayerId` / `team1PlayerId`
- 客户端据此判断「这场有没有我」和「我在哪边」
- 如果被分到队伍 1，就把**整个画面**左右镜像显示

**关键原则：只翻画面，不翻数据。**
传给内核算战斗的坐标永远是原始坐标 —— 所以翻转纯粹是画面层的事，完全不影响确定性。
代价是代码里多了一个「坐标边界」：3D 视图层用视角坐标，游戏逻辑层用原始坐标，
在 `handleBoardClick` 里转换一次。这个边界必须有注释说明，否则以后一定会有人搞混。

### ✅ 6. 数据表安全网（`validate-data.ts`，本轮新增）

**为什么先做这个？** 因为你以后加角色主要就是改 `unit-data.ts` 那张表。
改表最容易出这几类问题，而它们的后果差别很大：

| 你可能会犯的错 | 现在的后果 | 有了安全网之后 |
|---|---|---|
| 种族打错字（`knigt`） | **完全不报错**，只是那个棋子永远不参与羁绊 —— 几周后才发现 | 立刻报错，还会猜「你是不是想写 knight」 |
| 技能 id 撞车 | 不报错，但战斗日志里分不清是谁的技能 | 立刻报错，并列出是哪两个棋子 |
| 表格 key 和 `id` 不一致 | 运行时查不到棋子 | 立刻报错，指出两边分别是什么 |
| 血量为 0 / 射程为 0 | 要么崩、要么棋子永远打不到人 | 立刻报错 |
| `hp: 5500`（多按个 0） | 完全不报错，只是这个棋子变成神 | 提醒「强度分超量级上限，检查是不是多写了一位」 |
| 升星倍率填 1000 | 不报错，但升星没收益，玩家不想合成 | 立刻报错 |
| 打当前目标却忘写 `fallback` | 不报错，但技能会空放 | 提醒加 `fallback: 'nearestEnemy'` |
| 某个标签只有 1 个棋子用 | 不报错，但凑不出羁绊 | 提醒「这个标签凑不出羁绊」 |

**检查分两级，这个分级很重要：**

| 级别 | 含义 | 会不会拦住 |
|---|---|---|
| ❌ 错误 | 必须修，否则游戏会出问题 | 会。`verify` 直接失败 |
| ⚠ 提醒 | 建议看看，但可以是有意为之 | 不会。只提示 |

**为什么平衡性问题只提醒不拦？** 因为平衡最终得靠你拍板，工具不该替你做决定。
它只负责把「同费用里某个棋子比别人高一倍」这种事实摆给你看。

**实测验证**：我故意往数据表里注入 5 类错误（拼错标签、id 不一致、血量为 0、
技能 id 撞车、升星倍率错误），校验器**全部抓到**；恢复数据后立刻回到干净状态。

### 🐛 8. 踩过的真实坑（记录一下，避免重犯）

| 坑 | 现象 | 原因 | 修法 |
|---|---|---|---|
| **站位镜像** | 配对时报「棋子放错半场」 | 玩家提交的阵容永远是「自己视角」的左半边；服务端把其中一人放到队伍 1（右半边）时没翻转 | 加 `mirrorPlacements()`，队伍 1 的列翻转成 `7-c` |
| **准备阶段卡死** | 全员提交后房间停在 `prep`，永远打不起来 | 全员提交时只清了倒计时、没真正开始战斗 | 把「清倒计时 + 进战斗」收进同一个函数 `startBattlePhase()` |
| **校验和太弱** | 过程不同但结局相同的战斗会算出同一个校验和 | 只哈希了最终血量，没哈希过程 | 把整条事件日志（时间/目标/数值）全部混进哈希 |
| **随机种子形同虚设** | 换种子打出完全一样的战斗 | 技能都是固定数值，`rng` 从未被调用 | 用种子给每枚棋子一个 0–4 tick 的出手延迟抖动 |
| **协议方向搞反** | `checksumMismatch` 编译不过 | 它是「客户端→服务器」的上报消息，我一开始写进了服务器→客户端那一组 | 类型检查直接报错定位；挪到 `ClientMessage` |
| **新规则打破旧测试** | 加了「必须全员准备」后 10 个测试超时 | 旧测试直接调 `startGame`，从没点过准备；而且报错是「等待 gameStarted 超时」，看不出真因 | 统一在测试里补上准备步骤；但**专门测「不能开局」的那个用例要反向处理**，不能一起改 |
| **dev server 崩溃** | 改一次代码，开发服务器就整个退出 | 编辑器「原子写入」产生临时文件，Vite 的文件监视器在 Windows 上去 watch 它，报 EBUSY 直接崩进程 | 在 `vite.config.ts` 里把 `**/.*.tmpdir/**`、`**/*.tmp` 加进 `server.watch.ignored` |

| **★★ 对局结束后自己开了一局单机** | 服务器说游戏结束了，过一会儿却冒出人机阵容，还能继续打 | `onGameOver` 里把 `netplayActive = false`。这个变量被当成两个意思用："我在联机对局里" 和 "这一局打完了"。一关掉，客户端就真以为在单机：按钮文案换掉、`nextRound()` 前面的 `if (netplayActive) return` 也不再拦 | 拆出 `netplayMatchOver` 表示"这局打完了"，`netplayActive` 保持到**真正离开房间**（返回主界面/离开房间/断线）才清 |
| **★ 开新一局时沿用上一局的经济和阵容** | 先打一局单机（或上一局联机）再开局，场上还站着上一局的棋子、金币也是上一局的 | 单机开新局是 `state = createGameState()`，但联机的 `gameStarted` **没有**重建 state。写 `isMatchStart = !netplayActive` 时又正好被上一条影响 —— 打完一局后 `netplayActive` 还是 true，于是新一局被误判成"第 N 回合"，不但不重置，还白送一次回合收入（测试里 10 金 → 36 金） | 判断改成 `!netplayActive \|\| netplayMatchOver`（两个条件都要判），并在 `isMatchStart` 时重建 state。回归测试故意关掉重建验证过会红（`expected 36 to be 10`） |
| **★ 中文写进 `.cmd` 直接跑不起来** | 双击「启动游戏.cmd」，窗口一闪就没了 | cmd.exe 是按**当前代码页逐行解释** `.cmd` 的。文件存成 UTF-8 时，`echo 中文…` 里的中文被解析成乱码命令，报 `'??启动游戏' is not recognized as an internal or external command` | `.cmd` 内容**只留 ASCII**：`chcp 65001` + 调 node。所有中文由 Node 输出（UTF-8 在 65001 的窗口里正常显示）。**实测验证过**，不是推测 |
| **★ 测试"千分之一概率随机红"（自己写的测试坑自己）** | 偶尔 `prep-rules > 升级之后能上更多` 报 `Cannot read properties of undefined (reading 'uid')`；跑 55 次才出现一次 | 测试里写 `selectBench(state, state.economy.bench[0]!.uid)`，默认"买完备战席一定有棋子"。但商店是随机的：**三轮恰好买到同一个干员**时，三个一星会合成一个二星，而合成规则是"被吃掉的三个里有任何一个在场上，结果就落到场上"——备战席被清空。把 4000 个种子跑了一遍：**4 个会踩到（0.1%）** | 测试不再假设备战席里有东西：备战席空了就再买，合成产生的**场上**棋子同样算"上场了"。改成"找自己半场第一个空格"而不是 `ownCell(0, i)`。连跑 60 次全绿。**产品逻辑没错，错的是测试的假设** |
| **★ 测试依赖"打包产物"（和打包过程抢文件）** | `combined-server` 偶发 `expected 500 to be 200`；只有在我一边双击启动器（它在打包）一边跑测试时出现 | 那个测试用的是 `apps/web/dist`，而 `vite build` 会**先清空 outDir 再写入**。清空那一瞬间请求 `/` 读到不存在的文件 -> 500。这不是产品 bug，但让测试随机红 | 测试自己 `mkdtempSync` 造一个最小 `dist`（一个 index.html），和"打没打包""有没有人在打包"彻底解耦。故意在打包的同时跑，现在稳定通过 |
| **★★★ 服务器在"猜"客户端播完了没有** | 弱电脑/切过窗口的那台机器，战斗演到一半被掐掉、拉回布阵；两台机器看到的进度不一样（"双端不同步 / 直接跳过战斗过程"） | 服务器拿"这场战斗打了多少 tick"换算成秒数 `setTimeout` 等这么久就发下一回合。前提是"客户端回放速度 = 墙钟速度"，而这是错的：客户端主循环把单帧步长 cap 在 0.05 秒（防止切标签页回来瞬间播完），**帧率低于 20fps 时回放就比墙钟慢**（10fps 慢一倍），切窗口时浏览器还会把动画降频甚至暂停 | 新增协议 `playbackDone`：客户端在**本地回放真正结束的那一刻**举手，服务器**收齐所有参战者的回执**才进下一回合（快的人等慢的人）。另有兜底超时 `playbackFallbackMs`（等待时间 ×2 + 10 秒，上限 3 分钟）防止挂机卡死；有人掉线就从名单里摘掉。客户端结算时显示「等其他人看完战斗…」，不再是一个不动的「结算」。**用测试台 `--slow 1.8` 复现过（差 3.6 秒被截断）** |
| **★★★ 4 个人以上时，一半的人看的是别人的战斗** | 多人局里有些人看到的是别人那一场的战斗；胜负文案、伤害统计也跟着错 | 服务器会把这一回合**每一场**战斗都广播给所有人（方便旁观），而客户端"收到哪场就播哪场"，后收到的**覆盖**先收到的。配对 0 的两个人正好是"自己的先到、别人的后到"，于是被覆盖成别人的那场；配对 1 的两个人侥幸没事 —— 所以表现为"一半的人播错" | 规则改成"**自己的战斗优先，别人的不许覆盖**"：没在播 -> 挑第一场旁观；在播自己的 -> 别人一律忽略；在播旁观场 -> 自己的来了就换成自己的。**测试台 `--old-client` 复现过，单测用"回执里的 battleId"当铁证钉住** |

## 三、当前数值的已知问题

用占位棋子（9 个，1–5 费）跑出来的诊断结果，**这些问题等你的真实设计进来后会重做**，
但分析方法你可以一直用：

| 问题 | 数据 | 原因 |
|---|---|---|
| 蚀月（5费）超模 | 两两对抗 9 场全胜 | 全体 AOE + 2 秒群体眩晕，收益随敌人数放大 |
| 剑舞者（4费）超模 | 8 胜，只输给蚀月 | 1500 攻速 + 300% 单体 + 眩晕，数值过高 |
| 伤害/血量比例失衡 | 暗刃单挑 3.7 秒结束 | 战斗来不及展开，先手优势被放大 |
| 坦克互相打不死 | 骑士 3星镜像打 46 秒超时 | 护甲公式在高护甲段收益衰减太慢 |
| 骑士阵被刺客阵 30:0 | 连打 30 场全败 | 上述问题的综合结果 |

**读表方法**（以后你调数值时用）：
- 镜像对局胜率应该接近 50%，偏离越多说明「先手优势」越大
- 战斗时长普遍短于 8 秒 → 整体提高血量或降低伤害
- 对抗矩阵里某一行普遍很高 → 那个棋子超模
