# 怎么自己加一个角色

> 这份文档写给**不会编程**的人。照着抄、改数字就行。
> 你唯一需要打开的文件是：`packages/shared/src/unit-data.ts`

---

## 一、加角色的完整流程（4 步 + 素材 1 步）

### 第 1 步：把已有的棋子复制一份

打开 `packages/shared/src/unit-data.ts`，找到一个跟你想做的角色定位最像的棋子，
把**整段**复制粘贴到它下面，然后改内容。

比如你要做一个「2 费的火枪手」，就复制 `frost_mage` 那一段（它也是 2 费远程）：

```ts
  firegunner: {
    id: 'firegunner',
    name: '火枪手',
    cost: 2,
    traits: ['human', 'ranger'],
    base: { hp: 500, attackDamage: 75, attackSpeed: 1150, armor: 15, magicResist: 15, range: 4, manaPerAttack: 100 },
    starHpBp: 1800,
    starDamageBp: 1800,
    color: '#e08a4a',
    sprite: 'firegunner',
    skill: {
      id: 'firegunner_shot',
      name: '穿甲弹',
      desc: '对当前目标造成 240% 攻击力的物理伤害',
      effects: [{ kind: 'damage', target: 'currentTarget', fallback: 'nearestEnemy', power: 2400, damageType: 'physical' }],
    },
  },
```

### 第 2 步：检查数据

```bash
node scripts/pnpm.mjs check
```

它会用中文告诉你哪里写错了、为什么错、怎么改。**先过这一关再往下走。**

### 第 3 步：看战斗表现

```bash
node scripts/pnpm.mjs sim -- --seed 123 --stats --board
```

看战报里你的新角色有没有正常出手、伤害数字合不合理。

### 第 4 步：进游戏看

```bash
node scripts/pnpm.mjs web
```

浏览器打开 `http://localhost:5173`，左侧棋子库应该就有它了。

### 第 5 步（可选）：让新角色有头像和小人

**新加的棋子一开始就有"脸"** —— 程序会按你填的 `color` 画一张占位卡，
不用等图也能正常对局。想要真素材的话，跟我说一声，我跑这三个脚本：

```bash
node scripts/pnpm.mjs portraits:fetch --go   # 干员头像 + 半身像
node scripts/pnpm.mjs token:art --go         # 召唤物的立绘
node scripts/pnpm.mjs chibi:fetch --go       # Q 版小人（棋盘上动的那个）
```

**脚本默认只"预演"** —— 打印一份"哪个棋子匹配到了哪张图"的报告，一个文件都不下。
确认报告里没有 `<未匹配>` 再加 `--go` 真的下载。

**为什么第三个要单独拿出来？** 头像和立绘是现成的图片，下载就完事；
小人的原始形态是官方的 **Spine 骨骼动画**（骨骼 + 图集 + 贴图三个文件），
不能当普通图片直接用，得在构建期用无头浏览器**逐帧渲染成 PNG 序列帧**。
所以 `chibi:fetch` 会先抓骨架、再渲染，**中途会弹出一个浏览器窗口，慢一些**，是正常的。

素材放哪、跑完怎么确认生效，见 `docs/同人使用与版权说明.md`。

#### 召唤物（不会自己走路的那些）怎么有图

召唤物和干员用**同一张表**，只是多一个 `charId` 字段：

| 字段 | 填了会怎样 | 不填会怎样 |
|---|---|---|
| `charId` | 抓素材时会去官方镜像 / wiki 找它 | 只有占位卡，永远等不到图 |

`charId` 填官方素材里的编号（例：机械师是 `char_4230_mcnist`）。
**召唤物的官方目录比干员多一层皮肤文件夹**，所以有个别召唤物
（比如维娜·维多利亚的「黄金盟誓」金狮子）需要单独写死路径 ——
这件事也已经做进脚本了，你只要把 `charId` 填对就行。

## 二、每个字段是什么意思

| 字段 | 含义 | 怎么填 |
|---|---|---|
| 表格的 key（如 `firegunner`） | 程序内部用的名字 | 英文小写，不能和已有的重复 |
| `id` | 同上 | **必须和 key 一模一样**（写错了校验器会报） |
| `name` | 界面上显示的名字 | 中文随便写 |
| `cost` | 费用 1～5 | 决定它在商店里的稀有度和金币花费 |
| `traits` | 种族 / 职业标签 | **只能用合法清单里的词**（见下） |
| `color` | 棋子卡片的颜色 | 十六进制色值，可去网上「颜色选择器」挑 |
| `sprite` | 将来接真立绘时的图片名 | 现在随便填个英文名，暂时没用 |
| `charId` | 官方素材里的角色编号，抓头像/小人要用 | 见「第 5 步」；**不填就只有占位卡** |

### `base` 里的数值（最需要调的部分）

| 字段 | 含义 | 参考值 |
|---|---|---|
| `hp` | 血量 | 近战 500～1200；远程 400～700 |
| `attackDamage` | 攻击力 | 1费 50 左右，5费 110 左右 |
| `attackSpeed` | 攻速。**1200 表示每秒攻击 1.2 次** | 1000～1500，越高越快 |
| `armor` | 护甲。**减免率 = 护甲 ÷ (护甲 + 100)** | 坦克 30～50；远程 10～25 |
| `magicResist` | 魔抗。算法同上 | 一般 15～35 |
| `range` | 射程（格）。**1 = 近战，2～4 = 远程** | 近战填 1，远程填 3 |
| `manaPerAttack` | 每次普攻回多少法力。法力上限是 1000 | 100（即 10 下放一次技能） |

**护甲到底减多少？** 记这张表就够了：

| 护甲 | 物理减免 |
|---|---|
| 10 | 9% |
| 25 | 20% |
| 50 | 33% |
| 100 | 50% |
| 200 | 67% |
| 300 | 75% |

> 注意：护甲永远不会让你完全免伤，这是故意的（不然会出现打不死的棋子）。

### 星级倍率

| 字段 | 含义 |
|---|---|
| `starHpBp` | 每升一星血量乘多少。**1800 = 每星 ×1.8** |
| `starDamageBp` | 每升一星攻击乘多少 |

`1800` 意味着三颗星是 `1.8 × 1.8 = 3.24` 倍。两个都填 1800 就是通用做法。

## 三、技能怎么写

一个技能是**一串效果**，按顺序依次执行。每个效果 = 「打谁」+「干什么」。

### 打谁（`target`）

| 写法 | 意思 |
|---|---|
| `'currentTarget'` | 我当前正在打的那个人 |
| `'nearestEnemy'` | 离我最近的敌人 |
| `'farthestEnemy'` | 离我最远的敌人 |
| `'lowestHpEnemy'` | 血量最低的敌人（斩杀用） |
| `'highestHpEnemy'` | 血量最高的敌人 |
| `'allEnemies'` | 全体敌人 |
| `'enemiesInRadius3'` | 我周围 3 格内的所有敌人 |
| `'self'` | 自己 |
| `'lowestHpAlly'` | 血量最低的队友（治疗用） |
| `'allAllies'` | 全体队友 |

### ⚠️ 打单体时一定要写 `fallback`

```ts
{ kind: 'damage', target: 'currentTarget', fallback: 'nearestEnemy', power: 2400, damageType: 'physical' }
```

**为什么？** 放技能那一瞬间如果目标刚好被打死了，技能就白放了 —— 玩家会觉得自己的棋子很蠢。
`fallback` 就是"首选目标不在时改打谁"。

不写 `fallback` 不会报错，但校验器会提醒你。

### 干什么（`kind`）

| 写法 | 例子 | 说明 |
|---|---|---|
| 单体/范围伤害 | `{ kind: 'damage', target: 'currentTarget', fallback: 'nearestEnemy', power: 2400, damageType: 'physical' }` | `power` 是千分比，2400 = 240% 攻击力 |
| 治疗 | `{ kind: 'heal', target: 'lowestHpAlly', power: 1800 }` | 按**施法者攻击力**折算 |
| 护盾 | `{ kind: 'shield', target: 'self', power: 150, durationTicks: ms(4) }` | `power` 按**施法者血量上限**折算，150 = 15% |
| 眩晕 | `{ kind: 'stun', target: 'nearestEnemy', durationTicks: ms(2) }` | `ms(2)` = 2 秒 |
| 攻速增益 | `{ kind: 'buffAttackSpeed', target: 'allAllies', bonusBp: 2000, durationTicks: ms(5) }` | `2000` = +20% |
| 攻击力增益 | `{ kind: 'buffAttackDamage', target: 'self', bonusBp: 4000, durationTicks: ms(6) }` | `4000` = +40% |
| 回蓝 | `{ kind: 'gainMana', target: 'self', amount: 200 }` | 白给 0.2 条法力 |

**`damageType` 三选一：**
- `'physical'` 走护甲减免
- `'magic'` 走魔抗减免
- `'true'` 无视一切防御（慎用，很容易超模）

**`ms()` 是什么？** 是个小工具函数，把「秒」换算成游戏内部的 tick 数。
写 `ms(2)` 比写 `40`（tick 数）直观得多。

### 一个技能可以串联多个效果

```ts
skill: {
  id: 'firegunner_shot',
  name: '穿甲弹',
  desc: '对最近的敌人造成 240% 攻击力伤害，并降低其攻速',
  effects: [
    { kind: 'damage', target: 'nearestEnemy', power: 2400, damageType: 'physical' },
    { kind: 'stun', target: 'nearestEnemy', durationTicks: ms(1) },
  ],
},
```

效果按顺序执行，**每个效果都会重新选一次目标** —— 因为前一个效果可能已经把人打死了。

## 四、种族和职业只能用这些（重要！）

**写错的标签不会报错，只会让羁绊静默失效** —— 这是最难发现的一类 bug。
所以要加新标签，必须先去 `unit-data.ts` 里的 `TRAIT_KINDS` 登记：

```ts
export const TRAIT_KINDS: Record<string, 'race' | 'class'> = {
  // 种族
  human: 'race',
  night: 'race',
  // 职业
  knight: 'class',
  ranger: 'class',
  assassin: 'class',
  mage: 'class',
  priest: 'class',
  dragon: 'class',
};
```

**当前合法清单：**

| 标签 | 类型 |
|---|---|
| `human` | 种族 |
| `night` | 种族 |
| `knight` | 职业 |
| `ranger` | 职业 |
| `assassin` | 职业 |
| `mage` | 职业 |
| `priest` | 职业 |
| `dragon` | 职业 |

想加「精灵」就加一行 `elf: 'race',`，然后棋子就能写 `traits: ['elf', 'ranger']`。
如果你写了个没登记的标签，校验器会**猜你本来想写什么**并提示你。

## 五、改完一定跑这个

```bash
node scripts/pnpm.mjs check
```

它会给你这样一份中文报告：

```
  共 9 个棋子

  各费用数量：
    1 费   2 个  ██
    2 费   2 个  ██
    ...

  标签使用情况（羁绊是否凑得出来，看这里）：
    night      种族   6 个
    dragon     职业   1 个  ← 凑不出羁绊

  强度分（同费用之间横向比较，明显高的可能超模）：
    ── 1 费 ──  （2 个，样本太少不做离群比较）
      游侠             59
      铁壁骑士           19

  ✅ 没有必须修的问题
  ⚠ 建议看看的 3 个提示：
    [（全表）]  traits.dragon
      标签 "dragon" 只有 1 个棋子用。羁绊通常至少需要 2 个同标签的棋子
      才能触发，所以这个棋子现在凑不出任何羁绊。

  结论：可以直接运行。上面的提示只是提醒，不拦你。
```

**报告分两级：**

| 级别 | 含义 | 会不会拦住你 |
|---|---|---|
| ❌ 错误 | 必须修，否则游戏会出问题（拼错标签、技能 id 撞车、血量为 0…） | 会。`verify` 直接失败 |
| ⚠ 提醒 | 建议看看，但可以是有意为之（数值偏离同伴、标签凑不出羁绊…） | 不会。只提示 |

**「强度分」怎么用？** 它把血量和输出折算成一个数字，用来**横向比较同费用的棋子**。
同一个费用里，某个棋子明显比别人高一截，通常就是超模了。
注意它只是粗略参考 —— 真正准的是 `node scripts/pnpm.mjs balance` 里的实际对战胜率。

## 六、常见错误对照表

| 你写的 | 报什么 | 怎么改 |
|---|---|---|
| `traits: ['knigt']` | 不认识标签 "knigt"，是不是想写 "knight"？ | 拼写修对 |
| 表格 key 是 `firegunner`，但 `id: 'fire_gunner'` | key 和 id 必须一模一样 | 两边改成一致 |
| `skill.effects: []` | 技能里没有任何效果 | 至少加一个效果 |
| `hp: 0` | 必须是大于 0 的数字 | 填正常血量 |
| `starHpBp: 1000` | 必须大于 1000 | 一般填 1800 |
| 两个棋子都写 `skill.id: 'shot'` | 技能 id 被 2 个棋子同时使用 | 改成 `角色名_shot` |
| `base.hp: 5500`（多按个 0） | 强度分超量级上限 | 改成 550 |
| `target: 'currentTarget'` 没写 fallback | 提醒：目标死了技能会白放 | 加 `fallback: 'nearestEnemy'` |
| 某个标签只有 1 个棋子用 | 提醒：凑不出羁绊 | 再设计 1～2 个同标签的棋子 |

## 七、一次加很多角色时

**建议分批，每批 3～5 个，每批都跑一次 `check`。**
因为一次加 20 个再检查，报出 30 条问题时你会不知道从哪下手。

另外强烈建议**每批都跑一次** `node scripts/pnpm.mjs balance`，
看新角色和已有角色的对战胜率 —— 这比看强度分准得多。
