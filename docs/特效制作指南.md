# AIRNIGHT 特效制作指南

> 给「设计/制作特效的人 + 他的 AI 助手」看的一份说明。
> 目标：让你（或你的 AI）能在这个项目里**独立做出一套新的干员特效**，并且做出来就跟原来的风格一致、能过测试、能自己看到效果。
>
> 仓库：`AIRNIGHT`（明日方舟主题自走棋同人，网页版，3D 棋盘 + 2D 角色/UI）
> 代码目录：`版本文件/0.2.0测试/`（下文的路径都相对这里）

## 0. 先记住一句话（整份文档都从它推出来）

**战斗是一个纯数据的过程，画面是"照着数据演一遍"。**

内核（`packages/shared/`）跑完一场战斗只会留下一串**事件**（谁在第几 ticks 打了谁、掉了多少血、放了个范围技、挥了一刀……）。
渲染层（`apps/web/src/three/replay.ts`）就是**把这串事件播成动画**的那一层。

所以做特效的规则可以浓缩成三条：

1. **渲染层只读事件，绝不许自己重算规则。**
   不许"我按技能的半径算一下哪里该亮" —— 一定要问内核："这一跳到底打到了谁？" 由内核发一条事件，你照着画。
   理由很实在：你算的迟早和内核不一致（技能被打断、棋子中途死了、数值改了），画出来的东西就和伤害对不上。
2. **没有事件，就先加事件。** 加事件是内核侧 5 行的事（见 §5.6），而且它**不影响战斗结果**（表现层字段不进校验和）。
3. **表现层的任何东西都不许改变战斗结果。** 特效唯一允许做的事是"往场景里加/删自己的物体"。

### 你需要什么

- **这份代码仓库**（至少 `apps/web/` 和 `packages/shared/src/types.ts`）—— 特效代码要和它一起编译、一起跑测试。
- **Node.js 22 + 本机的 Edge**（唯一需要的浏览器；画汉字贴图、无头截图都靠它）。
- 不需要懂内核：**只有"现有事件不够用"时才去内核加事件（§5.6）**，而且那一步只碰 3 行。

## 3. ★ 事件菜单：你能用哪些"发生"来驱动特效

每条事件都带 `t`（第几个 tick）。下面这份表就是"这次要做什么表现"的选料台：

| 事件 | 关键字段 | 适合做什么表现 |
|---|---|---|
| `spawn` | `unitId, team, defId, star, cell, maxHp` | 出场动画、落地烟尘 |
| `move` | `unitId, from, to, instant?` | 走位残影、拖尾 |
| `attack` | `unitId, targetId, attackType` | ★ **普攻特效就挂这里**（= 命中帧） |
| `damage` | `sourceId, targetId, amount, damageType, attackType, absorbed, hpAfter, lethal` | 伤害数字、命中火花、击杀爆点（`lethal` 就是"这一下打死了"） |
| `heal` | `sourceId, targetId, amount, hpAfter` | 治疗光柱、绿色数字 |
| `shield` | `sourceId, targetId, amount, durationTicks` | 护盾罩子、罩子碎裂 |
| `status` | `sourceId, targetId, status:'stun', durationTicks` | 眩晕转圈（目前只有眩晕一种） |
| `dodge` | `sourceId, targetId, reason:'evade'\|'immune'` | ★ **闪避/免疫目前完全没有表现**，白捡的活儿（"未命中"的字样、一层突然亮起的护罩） |
| `zone` | `unitId, cell, radius, shape, kind:'damage'\|'heal', durationTicks, from?` | ★ **地面白框（范围指示）的唯一来源**，见 §4.4 |
| `slash` | `unitId, radius, shape` | ★ **多段斩击**，见 §4.2 |
| `buff` | `sourceId, targetId, stat, bonusBp, durationTicks, itemId?` | 增益上线的一道光、藏品给了谁 |
| `aura` | `unitId, stat:'armor'\|'magicResist', amount` | 羁绊光环加成数值飘字 |
| `mana` | `unitId, amount, manaAfter` | 技能条/回蓝闪光（**客户端技力条就是靠它更新的**） |
| `cast` | `unitId, skillId` | ★ **每个技能单独做特效的入口**（`skillId` 能精确区分是哪个技能） |
| `death` / `downed` / `rebirth` | `unitId, remaining` / `delayTicks` | 阵亡/倒地/二阶段复活 |
| `end` | `winner, reason` | 收尾演出 |

**两条已经探明的事实（可以直接利用）：**

* 全库 50 名干员里 **只有 30 个有主动技能**（另外 20 个是纯被动，`effects: []`，永远不会 `cast`）。加上野怪约 20、召唤物 5，**需要"每个技能都不一样"的其实是 30 套**，不是 300 套。普攻的那一套走"形状原型 × 参数（色相/尺寸/扫角/时长）"就够了。
* 每个技能的 `skillId` 在 `cast` 事件里带着 ⇒ 做"某个技能专属特效"不需要改内核，只要在 `replay.ts` 的 `case 'cast'` 里按 `skillId` 分派。

## 4. 已有的四种特效，分别是怎么做的

### 4.1 普攻特效 `attack-fx.ts`（**纯几何，没有任何贴图**）

- **三个家族**：`fxFamilyOf(def)` → `operator` / `monster` / `summon`，各一套预设（`attackFxPresetFor(def, {range})`）。
- **三块几何**：扇弧形（弧）、圆盘（爆点）、圆环（冲击环，只有野怪有）。
- **远近决定弧画在哪**：`RANGED_ATTACK_FROM = 2` —— 射程 ≥2 的弧画在**攻击者**脚下，近战的弧画在**目标**身上。
- **时长**：0.12~0.3 秒（`FX_DURATION_RANGE`），和"攻击前倾 0.18 秒"同一量级 —— 太长会显得黏。
- **触发**：`replay.ts` 的 `case 'attack'` → `spawnAttackFx(attacker, target, def)`（就是命中那一帧）。
- **上限**：`MAX_LIVE_ATTACK_FX = 48`，超了丢最老的（弱电脑保护）。

### 4.2 多段斩击 `slash-fx.ts`（月牙贴图 + 加色混合）

- 触发是内核的 **`slash` 事件**：范围持续伤害**每跳一条**（锏是 0.2 秒一跳 ⇒ 每 0.2 秒挥一刀）。
- **贴图**：canvas 现画月牙（径向渐变 + 刀刃细线），按"三档张角"缓存。
- **每刀形状不同**：`slashShapeOf(seq)` 用 `yaw = i*1.15 + 0.35`、张角 `i%3`、长度 `⌊i/3⌋%3` ⇒ 九刀九种组合。
- **尺寸**：刀长 = `radius * SLASH_CELLS_PER_RADIUS(0.8) * CELL * variant(0.82/0.94/1.06)`。
- **时长** `SLASH_DURATION_SECONDS = 0.44`（0.2 秒一刀 ⇒ 同时能看到 3 道；再长就糊成光幕）。
- **主题色是深黄**：高光 `#ffe08a` / 主色 `#e0a828` / 暗部 `#8a5c10` / 刀锋近白 `#fff0be`（用户口径）。

### 4.3 角色金色光环 `unit-aura.ts`（序列帧贴图，挂在卡片下）

- **两种**：`invincible`（无敌，常亮循环）和 `rebirth`（倒地等复活，强度 0.3→1.0 由暗到亮）。**优先级：重生 > 无敌**。
- **16 帧 × 0.05 秒 = 0.8 秒转一圈** —— "光华流转"就是这 16 帧连播。
- **尺寸看格子，位置看人**：世界尺寸 = `auraWorldSize()`（高 `CELL × 1.05`），而位置 copy 小人的。
- 它是**小人的兄弟节点**（都挂在卡片下），所以卡片移动/旋转/缩放时它自动跟随；`dropVisual` 里要记得摘掉。
- 层级用 `RENDER_ORDER_CHIBI + 0.5`（**用小数落在"小人"和"血条"中间**，以后谁调那两档都不用动这里）。

### 4.4 地面范围白框（`replay.ts` 的 `zoneShapeRects()`）

- 数据源是内核的 **`zone` 事件**：中心格 + 半径 + 形状 + **施法者所在格 `from`**。
- 把"形状 → 矩形列表"这一步抽成了**纯函数 `zoneShapeRects()`**，可以单独写测试：
  * 方形 = 一个大方块；十字 = 横一条 + 竖一条；
  * `line` = 从 `from` 朝 `cell` 推出去的长条（斜向**逐格画阶梯**）；
  * 老数据没有 `from` ⇒ 退回画方块（不允许崩）。
- ★ 这条踩过一次大坑：`line` 以前被画成"以目标为中心、半径 r 的方块"，玩家看到的就是"陈的技能是半径 3 格"——**内核本来就是直线**，错的全在界面。

## 5. 做一个新特效：标准流程

### 5.1 先确认"触发点"

问自己：这个表现对应内核里的哪个**已经发生的事实**？

- 想画"打中了" → `attack` / `damage`
- 想画"某个技能发动了" → `cast`（按 `skillId` 分派）
- 想画"某段时间里一直在转的圈" → 持续伤害每跳的 `slash`，或 `zone`（它带 `durationTicks`）
- 想画"身上挂了个状态" → `buff` / `mana` / `aura`

**如果找不到合适的事件，才进入 5.6（加事件）。**

### 5.2 新建一个模块

`apps/web/src/three/xxx-fx.ts`，只放两样东西：

```ts
// ① 纯计算：形状 / 曲线 / 尺寸 / 时长（全部 export，方便单测）
export const XXX_DURATION_SECONDS = 0.3;
export function xxxScaleAt(progress: number): number { /* 0→1 的曲线 */ }
export function xxxOpacityAt(progress: number): number { /* 淡出 */ }
export function xxxWorldSize(radius: number): number { /* 尺寸从 CELL 算 */ }

// ② 纯画法：造贴图 / 造物体 / 推进 / 销毁
export function xxxTextureOf(variant: number): CanvasTexture { /* 带缓存 */ }
export function createXxx(opts: XxxSpawnOptions): Xxx { /* 返回 { holder, parts } */ }
export function disposeXxx(fx: Xxx): void { /* 释放 geometry/material/texture */ }
```

**不要**在这个模块里读战斗状态（不许 `import` 内核的 state）—— 它只接收"位置、半径、队伍"这类已经算好的参数。

### 5.3 贴图（如果需要）

```ts
const texture = new CanvasTexture(canvas);
texture.colorSpace = SRGBColorSpace;   // ★ 必须写！不写颜色会被冲淡
texture.minFilter = LinearFilter;
texture.magFilter = LinearFilter;
texture.needsUpdate = true;
```

- 用浏览器 canvas 现画：**node 里没有字体引擎**，所以"渲染汉字 / 画渐变"这类事只能交给浏览器（这也是为什么项目的所有贴图生成脚本都用 Edge 截图）。
- **按"档位"全局缓存**：同一个档位永远拿到同一个 `Texture` 对象（战场上几十个单位同时发光也只占一份显存）。缓存要有单测（同参数两次必须 `toBe` 相同）。

### 5.4 几何与材质（贴地特效的固定配方）

```ts
const material = new MeshBasicMaterial({
  map,
  transparent: true,
  depthWrite: false,        // ★ 不写深度 ⇒ 不遮挡后面的棋子
  side: DoubleSide,         // ★ 贴地平面从上方看是一面，别让它背面消失
  blending: AdditiveBlending, // ★ "发光"用加色；不想要发光就别用
});
const mesh = new Mesh(geometry, material);
mesh.rotation.x = -Math.PI / 2;  // ★ 贴地
mesh.position.y = ZONE_Y;        // ★ 0.02，防 z-fighting（replay.ts 里的常量）
mesh.renderOrder = RENDER_ORDER_FX; // ★ 见 5.5
```

### 5.5 ★★ 层级：要压过棋子，靠的是 `renderOrder`，**不是抬高 y**

这是这个项目最反直觉的一条，务必记牢：

- 棋子卡面、小人、血条、技能条、星级**全部** `depthWrite: false`（透明物体不写深度）⇒
  **深度测试根本不参与"谁压谁"**，three.js 只能按"离相机的距离"排 ⇒
  跟卡面几乎同深度的贴地特效会**随机被卡面盖住**（锏的月牙就被盖过，用户报"特效被敌怪挡住"）。
- **正确做法**：设 `renderOrder`。层级定义只有一处 —— `card-layout.ts`：

| 常量 | 值 | 谁在用 |
|---|---|---|
| `RENDER_ORDER_CARD` | 0 | 卡面 |
| `RENDER_ORDER_CHIBI` | 1 | 小人 |
| `RENDER_ORDER_HP` / `RENDER_ORDER_SKILL_BAR` | 2 | 血条 / 技能条 |
| `RENDER_ORDER_STARS` | 3 | 星级 |
| **`RENDER_ORDER_FX`** | **20** | **所有"要压过棋子"的特效**（斩击、攻击特效） |
| （小数）`RENDER_ORDER_CHIBI + 0.5` | 1.5 | 角色光环 —— 夹在小人和血条之间 |

- 反过来：**别顺手写 `depthTest: false`**（那会让它盖住场上一切，包括别的棋子）。

### 5.6 加事件（当现有事件不够用时）

内核侧一共三小步（以"某技能要画一道光束"为例）：

```ts
// ① types.ts：给 BattleEvent 加一条（字段只带"表现层需要的最小信息"）
| (EventBase & { type: 'beam'; unitId: number; targetId: number; width: number })

// ② 发事件的地方（combat-math.ts 有 push(state, event) 助手；skills.ts 里没有，直接 state.log.push(...)）
push(state, { type: 'beam', t: state.tick, unitId, targetId, width });

// ③ ★★ computeChecksum() 里跳过它 —— 否则联机两端会对不上（表现层不许影响结果）
if (event.type === 'beam') continue;
// 顺手给 eventTypeCode 补一个号（不是为了参与哈希，是防"哪天这句 continue 被误删"时它
// 悄悄退化成和所有未知类型同号、还不报错）
case 'beam': return 19;
```

**判据**：如果这条事件会让"战斗结果"有一个数变化 → 它不是表现层的，别这么加。

### 5.7 接进 `replay.ts`（★ 三条生命周期路，一条都不能漏）

```ts
// a) 字段：private beamFx: BeamFx[] = [];
// b) 事件分支：case 'beam': { this.spawnBeamFx(event); break; }
// c) 每帧推进：this.updateBeamFx(deltaSeconds);
// d) ★ 播放结束那一帧的分支也要推进（这个分支在 replay.ts 里，跟 c 是两处）
//    —— 漏了它的症状：最后一下的特效永远停在场上（"火花一直贴在地上"）
// e) clear() 里清理：this.clearBeamFx();
// f) 上限保护：while (this.beamFx.length >= MAX_LIVE_BEAM_FX) 丢最老的
```

## 6. 铁律清单（提交前逐条过一遍）

- [ ] 渲染层**只读事件**，没有自己重算命中范围/半径。
- [ ] 新加的事件在 `computeChecksum` 里被跳过；**删掉它，战斗校验和不变**。
- [ ] 特效**不修改** `state.units`、不额外 push 事件（纯表现）。
- [ ] 贴地：`rotation.x = -90°`、`y = ZONE_Y (0.02)`、`DoubleSide`、`depthWrite:false`。
- [ ] 要压过棋子 → `renderOrder = RENDER_ORDER_FX`；要夹层 → 用小数；**不抬高 y**、**不用 `depthTest:false`**。
- [ ] 尺寸**从 `CELL` 或 `CARD_WORLD_SCALE` 算**，绝不由贴图像素数决定（`scale` 是世界单位，不是像素！）。
- [ ] 尺寸/层级只有**一处定义**，写成一个有名字的函数或常量（`xxxWorldSize()` / `RENDER_ORDER_*`）。
- [ ] 贴图按档位**全局缓存**；`CanvasTexture` 必须 `colorSpace = SRGBColorSpace`。
- [ ] 同屏**有上限**（丢最老的），并把它写进测试。
- [ ] 时长在 0.1~0.5 秒量级（太短看不见，太长糊成一片）。
- [ ] **加色混合下必须用饱和色**：接近白的颜色叠上去会发灰、像蒙了层雾（金色要 `#ffd058` 系）；
      棋盘左右半场本身就是蓝/红底 ⇒ 大块贴地特效别用队伍原色（红弧压红场读不出来）。
- [ ] 单位死亡/消失时，挂在它身上的东西要一起摘掉（`dropVisual`）。
- [ ] 新模块有单测（§7），`tsc` 0 错，`vitest` 全绿。

## 8. 怎么"看见"自己的特效（很重要，别看代码想象）

1. **先跑一遍真机**：`node scripts/walk-e2e.mjs`（无头 Edge + 真实 WebGL，截图写到 `.chibi-e2e/`）。
   常用参数：`--keep-open`（不关浏览器，自己接着点）、`--port 5291`（换端口）。
2. ★★ **拍特效必须"探针触发式"**，不能按固定时刻连拍：
   特效只有 0.1~0.3 秒，攻击间隔近 1 秒 ⇒ 连拍三张全落在两次攻击之间，看起来像"根本没做特效"（这是真踩过的坑）。
   做法：`?debug=1` 打开探针（`__airnightAttackFxProbe.sample()` 会给出"现在场上有几块特效、都是什么家族"），
   轮询到"特效数 > 0"的那一刻再截图。探针都在 `apps/web/src/three/debug-probe.ts` 里。
3. **要单独调一个特效的观感**时，做一张**提案页**（项目里的例子：`.fx-proposal/` 与 `.aura-preview/`）：
   - ★★ 关键：**用 esbuild 把真模块打成一份 iife**，让页面调**真代码**。
     照抄一份画法出来做预览页 = 截图会骗人（改了真代码、预览页还是旧的）。
   - 想看"真 WebGL 下的效果"（贴地、加色、透视、世界尺寸对不对）就用真 three.js + 无头 Edge + swiftshader：
     `--headless=new --use-angle=swiftshader --enable-unsafe-swiftshader`
     （现成的启动参数抄 `scripts/chibi-e2e.mjs` / `scripts/walk-e2e.mjs`）。
   - 想看贴图本身（渐变、切片、颜色），只截图 canvas 就够。
4. ⚠️ Edge 的 `--user-data-dir` 会生成 200 多个文件，`rm -rf` 会被安全删除拦住 ⇒ 用 `cmd //c "rd /s /q <目录>"` 清。
5. ⚠️ 路径里有中文和空格：脚本里取路径**必须用 `fileURLToPath(new URL(...))`**，
   直接用 `new URL(...).pathname` 拿到的是**百分号编码**路径，会静默把文件写到错误的目录里。

## 9. 真实病历：这些坑都是用"看起来没问题"的代码踩出来的

| 症状 | 根因 | 正确做法 |
|---|---|---|
| 光效"巨大一个、比竞技场还大" | 把**贴图像素当世界单位**写死 `scale = 128 × 1.15`，而卡片世界尺寸只有 0.72×0.96 | 精灵的 `scale` 是**世界单位**；尺寸从 `CELL`（`auraWorldSize()`）算 |
| 贴地弧"糊成一块暖色，读不出来" | 用队伍原色（`0x8fd0ff`/`0xff9a9a`）画大块贴地特效，压在蓝/红半场底色上 | 另配提亮色 `FX_GLOW_COLORS`（近白）；弧的内外半径比从 0.5 收到 0.62（0.5 太厚） |
| 月牙变成"一把扇子 / 一道道竖棱" | canvas 里按角度切片做两端渐隐，切片重叠给了 0.06 弧度（≈3.4°），普通合成下 alpha 累加 | 重叠量必须极小：**0.003 弧度** |
| 连斩"像风车在转" | 形状序号用了 `(i*5)%3`、`(i*7)%3`，其实是 `2i%3`、`i%3` ⇒ 九刀只有 3 种组合 | 用互质的步进：`yaw = i*1.15 + 0.35` |
| 最后一下的特效**永远留在场上** | 只接了"每帧推进"，忘了播放结束那一帧的分支（两处都要推） | 三条生命周期路（每帧 / finished / clear）一个都不能漏 |
| 刀光被敌怪挡住 | 特效和卡面几乎同深度，而两边都是透明物体（不写深度）⇒ 只能按距离排 | 设 `renderOrder`（`RENDER_ORDER_FX`），**不是**抬高 y；也**别**用 `depthTest:false` |
| 单位死了，光效还留在原地 | 光效是独立精灵，`dropVisual` 没摘它 | 挂成卡片的子节点（跟随自动成立）＋ `dropVisual` 里移除 |
| 光效"金色"看着发灰、像蒙层雾 | 加色混合天然往白走，第一版用了接近白的色值 | 用**饱和**的金（`rgba(255,208,88)` 系） |
| 特效"像根本没做" | 按固定时刻截图，全落在两次攻击之间 | 探针触发式拍照（§8） |
| 一场剑雨把弱机卡住 | 没设同屏上限 | `MAX_LIVE_*` + 丢最老的 |

> 你正在给「AIRNIGHT」（网页版自走棋，TypeScript + three.js，仓库在 `版本文件/0.2.0测试/`）做**一个干员技能的特效**。
