（相对 0.3.31 正式版）

一、★★ 胜负判定 / 连胜连败（用户报的"小概率"现象）
------------------------------------------------
· **症状**：偶尔"输了却不掉血 / 赢了却掉血又断连胜"。
· **根因**：回合结算判"我这一回合赢了没有"时，读的是**屏幕上那一场**战斗
  （`currentResult` + `myTeam`）。而这两样会被**观战**改写 ——
  打完自己的那场、点别人的对局看一眼，`currentResult` 就变成别人的战斗，
  `myTeam` 也会被算成 0（我两边都不是）。于是：
    · 别人那场左边赢 → 我输了也记一胜（不扣血、连胜不断）；
    · 别人那场左边输 → 我赢了也记一负（断连胜 + 按输结算）。
  只有"回合切换那一刻正好在看别人"才会中招，所以显得随机。
· **修法**：给"我自己那一场"单独记一份账本（`game/battle-outcome.ts`，纯函数 + 单测）。
  自己那场开播时写进去，收到服务器的 `battleEnd` 再把**服务端胜负**补进去（以它为准）；
  连胜/连败、奸商存活名单、战利品、fever、阿米娅任务伤害全部只读这份账本。
· 服务端这条账另补了回归用例：赢的人不掉血、输的人一定掉血、
  平局两边都不动、影子对战只动轮空者、1/5/6/10/11 回合分别扣 3/3/6/6/9。

二、★ 结算横幅改版（胜利 / 战败 / 平局）
------------------------------------------------
· 从"中间一块圆角卡片"改成**横向通栏状态带**：贴边、上下 1px 细线、
  左侧一根 3px 竖色条（胜 = 荧光黄绿，败 = 红，平 = 灰）、
  中文大标题 + 字距拉开的英文小标注（VICTORY / DEFEAT / DRAW）+ 右侧等宽数据。
· 从顶部滑入，下方一条细线从左擦到右，停留两秒多自动收走；
  `pointer-events: none`，不挡摆棋子（一局二三十回合，不能每回合点一下）。
· 联机打完一整局也走同一条横幅（冠军 / 第 N 名），压在战绩页上方几秒。

三、★ 「再来一局 · 返回房间」
------------------------------------------------
· 联机结算页底部新增主按钮「再来一局 · 返回房间」：房间退回大厅，
  **房间号、座位、房主、房间设置都不变**，所有人一起回去，房主直接再点开始就是下一局。
· 服务端复位：血量回到房间的「开局血量」、战绩 / 连胜连败 / 准备状态 /
  盟约 / 淘汰标记 / 牌库 / 商店预定全部清空。
· 只有"这一局已经打完"才允许；对局进行中会拒绝（避免一个人单方面解散对局）。

四、★ 调试读数默认隐藏
------------------------------------------------
· 结算横幅上的「校验和 0x…」、状态栏里的「种子 123456」、
  以及「战斗开始（本地重放，校验通过）」这类内部口径，**默认不再显示**。
· 需要排查确定性问题时，地址栏加 `?debug=1` 就会重新出现（控制台那份一直保留）。

五、★ 窗口自适应（小窗口不再挤、大窗口保持原样）
------------------------------------------------
· **症状**：1280×720 这类小窗口下，顶栏那排数字挤到换行、右端的
  「日志 / 玩家 / 藏品」被裁掉，商店 5 张卡横向溢出、第 5 张只剩一半。
· **做法**：以 **2560×1600 全屏为设计基准（缩放 = 1.0）**，整套 UI 按窗口算一个系数
  （`min(宽/2560, 高/1600)` 再线性映射到 0.8~1.0，夹住下限），
  用布局级的 `zoom` 套到顶栏 / 羁绊栏 / 日志栏 / 底栏 / 战斗条（+ 主界面与结算页的内容块）：
    · 2560×1600 = 1.0 —— 和以前**一个像素都不差**（面板 190/250、底栏 280、字号原样）；
    · 2560×1440 = 0.96；1920×1080 = 0.88；1440×900 = 0.84；1366×768 = 0.81；1280×720 = 0.80；
    · 比 2560×1600 更大的屏**不再放大**（1.0 封顶），保持这套比例；
    · 3D 战场不缩放 —— 它本来就是按"没被 UI 挡住的那块区域"由相机自己框的。
· 1280 以下把商店卡最小宽度从 190 收到 160，5 张刚好放得下（不再需要横向滚动）。
· 实测 1024 / 1280 / 1366 / 1440 / 1600 / 1920 / 2560×1440 / 2560×1600 八档：
  顶栏、底栏、商店、备战席**全部无横向溢出**。

零、★ 人机与羁绊修复（实机一局反馈）
------------------------------------------------
· ★★ **人机不会逛商店回合** —— 两个原因，都修了：
  · 回合号错位：服务端广播的 `round` 已经是**新**回合号，而 `advanceRound` 判完
    "这一回合之后要不要开商店"才会 +1。人机以前直接照抄 ⇒ 判据被抬高了一格，
    开商店比服务端早一回合，真到商店那回合手上还是上一份旧货架。
    现在进 `advanceRound` 前先退回"刚打完的那一回合"。
  · **普通 / 简单档根本没开这个开关**（只有困难档开了）。商店回合是对局的**一个阶段**，
    不是"高级技巧" —— 现在三档都会逛（难度差保留在"买什么"上）。
    实测：给 120 金进商店回合，以前一件都不买，现在 8 格货架会按性价比买下来。
· ★★ **人机只买转职** —— 转职藏品以前是**固定 30 分**，跟一件毫无用处的普通藏品同价，
  于是它每格都买，哪怕那个羁绊场上一个人都没有（转了也没意义）。
  现在按阵容打分：**家里本来就在跑这个羁绊、且差一个人就能升档 ⇒ 最值钱**；
  家里一个都没有 ⇒ 0 分，直接不买。
· ★★ **备战席一堆废牌不卖** —— 触发清理的门槛从"满 8 格"降到 **5 格**，
  满席时的出手线也从 40 抬到 60；而且**手上已经有 2 张同名的绝不会卖**
  （卖掉等于前面两张白投）。实测 9 张牌会清掉 4 张。
· ★★ **后期不买五费** —— 以前只有 `费用 × 6` 的权重，5 费才 30 分，
  跟"两张 2 费 + 对子加成"差不多 ⇒ 它宁可攒三个杂鱼也不碰五费。
  现在中后期（第 10 回合起）给 4/5 费额外加权（4 费 +10、5 费 +20）；
  顺手改掉一条：以前"没有羁绊支撑就别买"连 5 费一起压，现在**只压 4 费**。
  另外困难档的等级曲线放到 **9 级**（8 级时 5 费出货率只有 3%，9 级才 10%）。
· ★★ **回血藏品有时候不生效** —— 两个坑，都填了：
  · **服务端夹上限时漏了盟约加血**：`healPlayer` 只拿 `settings.startHp` 当上限，
    可带了「歌利亚」（+30 上限）的人血量是 130 ⇒ 吃回血藏品被夹回 100，**越吃越少**。
    现在和服务端 `applyCovenantWinHeal` 走同一个口径（`startHp + 盟约加成`）。
  · **客户端完全不夹上限**：以前是 `hp += n`，单机里数字能涨到 105 / 130，
    联机里服务端一夹、下次广播又被覆盖回来 ⇒ 玩家看到"装了完全没反应"。
    现在收敛成 `applyPlayerHeal` 一个入口，两边同一套规则；
    满血时提示写「血量已满」而不是谎报「血量 +15」，
    **纯回血藏品满血时直接拦下不销毁**（热水壶还带金币，所以放行）。
· ★★ **卡西米尔有概率不召唤援军** —— 根因找到了：
  开局结算里写的是「挑第一个上场的单位当发言人，只读它的机制表」，
  而机制表是按 `defId` 挂的，只有**这条羁绊的成员**才有。
  `myUnits[0]` 是谁取决于**你第一个摆的是谁** ——
  所以它"有时候有、有时候没有"，而且不报任何错。
  现在改成扫**所有**成员并按「机制属于谁」去重（同档援军仍然只召唤一次）。
  「支援」的双抗加成是同一个坑，一起修了。
· ★ **全羁绊对拍排查**：写了个对拍探针，把 21 个羁绊逐个和"空羁绊"
  跑三种场景（静止 / 挨打 / 带治疗）比对属性与事件。
  结果：19 个正常；**奸商**是经济类效果（回合结算给金币），战斗里本就无差异（不是 bug）；
  **治疗**就是上面那条修好的 bug。

修掉的问题（都是实地踩出来的）
------------------------------------------------
· ★★ **对局里点「图鉴」什么都不发生**。
  根因：整个图鉴浮层被写在了 `#main-menu` 内部，而进对局后 `#main-menu` 是 `display:none`

  盖得住大厅 / 盟约 / 设置（100），但盖不住"必须处理"的那几层
  （商店回合 360 / fever 380 / 暂停 390 / 重连 400）。

    · 普通攻击 = **黑墨斩击**（刀身是一块普通混合的墨 —— 纯黑在发光混合下不可见，

      敌人身上还会留一道**黑色的受击刀痕**（普通混合墨底 + 青刃口）。
    · 技能 = 三色齐全：施法那一刻脚下**黑墨腾起 + 青色墨光 + 红色火星**；
      技能期间每一刀都是黑刃 + 青刃口，命中处再炸一朵**红色火花** ——
      红是"怒火"，只在技能里出现，而且落在被打的人身上（和青刃错开位置，
      不然红+青会被发光混合冲成白色）。
    · 三种颜色各占一条刀的不同浓度带（暗部=黑、亮部=青、最亮的芯=红），天生不打架。

  · **慈悲愿景的专属特效（柔亮粉系 · 短暂集中爆发）**：
    · 普通攻击 = 粉色法术弹，从出手到命中同一套粉调（弹体 / 尾迹 / 命中光晕都不变色）。
    · 技能 = **只在真正造成伤害的那一瞬**，在她前方那 12 格（宽 3 × 深 4）铺一层粉色方格阵：

        所以"画出来的范围"必然等于"实际打到的范围"（空放不铺）。
  · **炉芯终曲的专属特效（暗黑破碎 · 氛围化弥漫）**：
    · 普通攻击 = 黑色法术弹（黑芯 + 暗红断口 + 冷高光；纯黑在发光混合下看不见，必须分三层画）。

        多报一条纯表现事件 `executeFx`（不进校验和，不影响联机一致性），渲染层照它播。

失序协议 0.3.1 正式版（2026-10-21）
================================================

------------------------------------------------
一、★「迅捷作战粮」：描述和效果对不上（改了效果）
------------------------------------------------
卡面写的是「攻击 / 受击 / 技能**回复量** +50%」，数据里却挂成了**治疗效果 +50%** ——
一件"作战粮"变成了治疗装，等于完全没有描述的收益。
现在改成真的加**技力回复**：三条回蓝路（攻击回复 / 受击回复 / 自动回复）统一 +50%，
和卡面一致。

------------------------------------------------
二、★「拳经三问」：改成**跨回合成长**
------------------------------------------------
以前是"一场里每开一次技能 +5%，最多 20 层"，但**战斗一结束就清零** ——
一件进阶藏品基本吃不满，下一场又从 0 开始。
现在改成**每经过一个回合 +5% 攻击力**（上限 20 层），跨回合累积；卸下装备清零
（和仇名录 / 佣兵的饰物同一套口径）。

------------------------------------------------
三、★ 盟约界面：点头看详情时，右边的头像只露出一小块
------------------------------------------------
详情里那个头像原本内联写死 26×26，而"铺满"的规则只写在卡片上 ——
图片按原始尺寸（75×75）铺开、被外框裁掉，只剩左上角一小块。
现在尺寸和铺法都归样式表管，顺便放大到 34×34，和标题更配。

------------------------------------------------
四、★★ 盟约选秀阶段有人掉线：不再暂停、也不再卡住倒计时
------------------------------------------------
以前（以及"看起来"）的问题是：选秀里有人掉线会弹「对局暂停」浮层，
倒计时也跟着不动，全房间只能干等。
现在：
· 选秀阶段**永不暂停** —— 它本来就有每人 30 秒的超时兜底，再叠一层"等掉线的人"只会让人以为坏了；
· 谁掉线、而且正好轮到他 —— **立刻替他随机选一个**，不用等满 30 秒；
· 选秀结束后如果还有人没回来，改在**布阵阶段**停一次（避免他第一回合空手挨打）；
· 客户端再加一道：选秀页面上**永远不显示**暂停浮层；房间广播每秒也会校正一次倒计时基准，
  即使某条倒计时消息丢了，数字也不会卡住。

------------------------------------------------
一、★★ 选秀倒计时"不动"（用户报的，也是本项目的老毛病）
------------------------------------------------
根因：**秒数只搭在"房间广播"这一条通道上**，而且写在一个会被结构签名挡住的函数里。
任何一次节流、去重、渲染异常，数字就停在原地。
这类"倒计时不走"在这个项目里已经出现过**四次**（布阵 / 暂停 / 商店回合 / 这次）。

**现在的规矩（以后新加倒计时照这个来）：**
1. 每个有倒计时的阶段，必须有**一条独立的、只服务倒计时的 tick 消息**
   （已有：`prepTick` / `pauseTick` / `shopTick`，这次补上 `covenantTick`）；
2. 客户端拿这条消息只做一件事：**记一份"服务端说还剩 N 秒 @ 本地时刻"的基准**；
3. 数字由**每帧**按墙钟换算出来写进 DOM（不是"收到消息才写一次"）——
   这样哪怕某条 tick 丢了，数字也会继续往下走，下一条 tick 再校正回来。
4. **绝不能本地自己减 1** —— 网络抖一次就永久差几秒。

四、★ 联机：修「阵容被判非法之后重进会丢棋子」
------------------------------------------------
· **原来的问题**：阵容里只要有一个格子不合法（两枚棋子压同一格 / 站位越界 /
  认不出的干员 id），服务器就**整份拒收**。于是玩家重进游戏时，服务器手上还是
  更早的那一份阵容 —— 他这一回合摆的棋子、备战席、金币全部回退，看起来就是"我的棋子没了"。
· **现在**：坏的那几个单独扔掉，**剩下的照常参战**（少一个，而不是整份不算），
  并且立刻提示"有 N 个棋子的站位数据不合法，这次同步已忽略它们"。
· 一个都不剩时才整份作废，但**服务器仍然把这份数据记下来**，
  所以重进时还是能把你看到的棋盘/备战席/金币原样装回去。
· 顺带修好了另一个"重进丢数据"的成因：以前判断"要不要用服务器那份还原棋盘"，
  靠的是浏览器**标签页**里的一个标记 —— 关掉浏览器、或者换个标签页重新进游戏时
  那个标记是空的，于是**拒绝还原**，棋盘直接归零。现在改成看"这一页有没有装载过这一局"，
  新开的一页一定会还原。
· 另外：淘汰时"把手牌还回共享牌库"也改成按**最新那一份**快照算 ——
  以前阵容判非法的那一回合刚好被淘汰，这一回合买的牌会**永远回不了牌库**（牌库静默少几张）。

  血镰全部挂到这一层下面，而这一层的 `raycast()` 返回 false ——
  整棵子树都不参与拾取，射线直接穿过去打到棋子。

0.2.1 追加十八（2026-10-17 晚五）—— 断线重连"点了没反应"的四个根因
================================================
现象：断线之后大部分重连尝试**什么反应都没有** —— 不报错、不回座、也不重试。
令牌一直在手上，所以问题不在令牌，而在**连接层会静默卡死**。

查下来是四条，每一条都会让"重连引擎"停摆，而且都不出声：

1. **建连卡在"正在连接"时，所有重试都是空转**
   撞上地址黑洞（隧道挂了 / 机器休眠 / 换了网络）时，浏览器建连要等**操作系统**
   TCP 超时，几十秒起步。这期间每次重试都被"已经有一条在连了"挡回去，
   玩家点多少次都一样。现在加了 **8 秒建连超时**：到点就作废这条、另起一条。

2. **心跳判死之后只关连接，不安排重连**
   半死连接（休眠唤醒 / 路由表项过期）收不到对方的关闭消息，
   "连接已关闭"这个事件可能几分钟都不来 —— 而重连恰恰只写在这个事件里。
   表现就是提示写着"正在重连"，实际上一次都没有重连过。
   现在心跳判死会**主动作废连接并立刻重排重连**，不再干等。

3. **旧连接的"已关闭"会污染新连接**
   事件回调不检查"这条连接还是不是当前那条"，于是旧连接迟到的关闭消息
   会把新连接的"已连接"打成断开、把房间清空、把心跳停掉 ——
   明明连上了，界面却永远停在"正在重连"，而且再也不重试。
   现在每条连接都带身份校验，旧连接的任何事件一律丢弃。

4. **"立即重试"在连接还开着时是空操作**
   `resume` 发出去服务器没回话时（异常 / 半开连接），界面停在重同步浮层，
   而这时连接是开着的 —— 点「立即重试」会被"已经连着"直接挡住。
   现在「立即重试」= **真的重来一次**（作废旧连接再连），
   而且 `resume` 发出去 8 秒没人回答会自动重来，不会一直挂着。

顺带两处：

· 手上没有令牌时点「立即重试」，现在会明说"没有重连令牌，只能重新加入房间"，
  不再装作在重试。
· 「回到对局」在"连着但身份没换回来"（令牌比连接晚到）时会主动重来一次；
  连上却没有令牌可换身份时，重同步浮层会立刻收掉（不再永远盖着）。

------------------------------------------------
以前是**跨过一个新档位就白给一份宝藏** —— 于是只要一直点「保留」把 fever 攒着，

8 人档写的是「回合结束时当前 fever 翻倍」。上一版按字面实现成
**把攒下来的总额翻一倍** —— 实测 8 人一场能攒 240 左右，于是

  · 第 1 回合 480、第 2 回合 960、第 3 回合 1440 …第 7 回合 3360
  · 七档掉落表刚好铺满一局的中后期，节奏对上了。

三、★ 老蒲扇：只数"已经激活的"羁绊

提示里原来写的是「当前 N 个羁绊」，但那个 N 把"有人带着这个标签、

0.2.0 测试版 追加七（2026-10-17 下午）—— 新机制「商店回合」

------------------------------------------------
一、它是什么
------------------------------------------------
每打完一个**野怪回合**（第 1、2 回合不算 ⇒ 实际是第 9、16、23、30… 回合之后），
会插入一个 **90 秒**的商店阶段：屏幕正中弹出**坎诺特**（集成战略里的古怪商人）的绿色商店。

二、卖什么（8 个货架）
------------------------------------------------
| 槽位 | 数量 | 价格 |
|------|------|------|
| 普通藏品 | 4 | 8 金 |
| 进阶藏品（**不含转职**） | 2 | 16 金 |
| 干员棋子 | 1 | 3 × 费用 |
| 转职藏品 | 1 | 12 金 |

· **刷新**：第 1 次 4 金、第 2 次 8 金、第 3 次 12 金、第 4 次起都是 16 金。
  ★ 次数只增不减 —— 买走两格再刷新**不会**降价（不然可以靠"买空再刷"绕过涨价）。

★★ **每次死都掷，但每复活一次概率 -10%**（减的是百分点，不是"乘 0.9"）：

| 人数 | 第 1 次 | 第 2 次 | 第 3 次 | 第 4 次 | 第 5 次 | 最多站 |
|---|---|---|---|---|---|---|
| 2 人 | 30% | 20% | 10% | 0 | — | **3 次** |
| 3 人 | 40% | 30% | 20% | 10% | 0 | **4 次** |
| 5 人 | 50% | 40% | 30% | 20% | 10%（→0） | **5 次** |

概率降到 0 之后就不再掷骰（也不会白耗一次随机数）。
递减量是一个全局常量（`UNYIELDING_CHANCE_DECAY_BP`），以后想改成 -5% 或 -15% 只动一个数。

------------------------------------------------
二、★★ 「必定复活藏品」优先：M3 茧甲 > 不屈
------------------------------------------------
你点名的那条已经落实：**有茧甲时先判茧甲**，不屈当兜底。
所以带茧甲的棋子第一次死一定吃茧甲（满血站起来），**不屈那次判定留着** ——
第二次死才轮到不屈掷骰。这样两件效果不会在同一次死亡里一起用掉。

（多阶段 Boss 的"二阶段重生"走的是同一条 `reborn` 通道，所以也是它优先。）

------------------------------------------------
三、★ 成员：砾 / 耀骑士临光 / 伊内丝
------------------------------------------------
三个人的标签里都加上了「不屈」，另外顺手多出一件**「不屈转职」**藏品
（转职藏品是跟着羁绊表自动生成的，凑 5 人档只有 3 个成员，没有转职永远凑不齐）。

------------------------------------------------
四、★ 「立刻释放一次技能」对纯被动棋子也生效了
------------------------------------------------
砾、耀骑士临光、伊内丝的技能都是**纯被动**（没有"主动效果"那一栏），
原先灌满法力也没东西可放。现在按你说的做了分流：

| 棋子类型 | 复活后"释放一次技能"是 |
|---|---|
| 有主动技能 | 法力灌满 → 当帧按正常流程放一次（老行为） |
| **纯被动、且带「开局效果」** | **把开局效果重新应用一次** |
| 纯被动、没有开局效果 | 安静地什么也不做 |

对号入座：
· **砾** —— 开局效果是"生命上限 75%/95%/125% 的护盾 + 35 护甲/魔抗（10 秒）"
  ⇒ **复活后护盾和双抗刷新一次**（你点名要的那条）。
· **耀骑士临光** —— 被动是"队友残血时瞬移给盾"，属于**事件型**钩子（要靠队友残血触发），
  不是"用一次就没了"的开局效果，所以复活后不额外触发。
· **伊内丝** —— 被动是"每次攻击削目标攻速"，同样是事件型，同上。

★ 小提示：实战里旧护盾一般已经被打破了（不打破就打不死），所以观感就是"刷新"；
  万一那次是**真实伤害**绕过护盾打死的，旧盾还在，这一下会叠加成两层。

------------------------------------------------
一、★★ 维什戴尔 3 星「爆裂黎明」有了专属的 5×5 红黑爆炸
------------------------------------------------
到 3 星之后，技能给的 6 发弹药每一发都会变成 5×5 群体物理伤害 ——
现在**每一发打出去都会在那一格炸开一片红黑色爆炸**（10 帧 / 每秒 24 帧 / 0.42 秒），
图层压在所有棋子之上，不会被棋子挡住。

这套爆炸是**三层叠出来的**，每一层的混合方式不一样，这是关键：
  · **黑烟**（普通混合）—— 真正的黑，往上飘并铺开；
  · **火焰主层**（加色混合）—— 白热闪光 → 火球 → 冲击环 → 铺满 5×5 的火墙 + 火舌 + 上飘火星；
  · **中心炸点**（加色混合）—— 中间那一下最亮的爆闪。
★ 为什么"黑"要单独一层？因为游戏里贴地特效一律是**加色混合**（把颜色加到地面上），
  而**纯黑加进去等于什么都没加、完全看不见** —— 所以主层里的"黑"是深红（#84120e / #2c0604），
  真正的黑靠单独那层烟（把地面遮暗）。

"炸在哪、炸多大"完全跟着**数据**走：技能数据里给这一发溅射标一个 `fx: 'vishdal_bloom'`，
内核就会在结算那一刻多报一条"爆炸"事件，界面照着注册表取图。
⇒ 以后要给别的干员加爆炸，只要数据里写个名字 + 加一行图，不用改内核逻辑。

★ 顺带说明一个**故意的**差异：地上的**范围白框**还是只在"真的打到了第二个人"时才闪
（单挑时地上亮一个 5×5 方框是假的）；但**爆炸照炸** —— 因为这技能本身就是"变成 5×5 群伤"，
只命中一个人它也是一次 5×5 爆炸。要是你希望"没人可打时也不炸"，说一声，一个判据的事。

------------------------------------------------
二、★★ fever 弹窗：同一个档不再反复问
------------------------------------------------
以前每回合都会问一次"到档了，要不要消耗"——你选了几次「保留」就要被问几次。
现在**只在新跨过更高的档时才弹**：

  第 3 回合 50 点 → 不弹
  第 4 回合 150 点 → 弹「100 档」
  第 5 回合 170 点 → 不弹（还在 100 档里）
  第 6 回合 400 点 → 弹「300 档」
  第 7 回合 460 点 → 不弹

★ 掉到这一档**下面**再涨回来，会重新弹（比如从 300 档掉到 100 档，再涨回 300 就又问一次）。
★ 点了「消耗」把 fever 清零之后也一样：重新攒到 100 就会再问一次，不会因为"问过 300 档"就再也不问。

------------------------------------------------
三、★ 受击回复法力：改成固定 100
------------------------------------------------
以前是"按受到的伤害折算"（物理 0.2%、法术 0.08%），于是**挨得越疼充能越快**，
而且玩家在详情页根本算不出"还差几下能开技能"。
现在**固定回 100**（法力上限 1000）⇒ **挨 10 次打必定开一次技能**，
和「每次普攻回 100」完全对称、也好跟玩家解释。

0.2.0 测试版 追加（2026-10-16 晚）—— 炎燃烧 / 陈的范围 / 锏的刀光 / 望的棋子
================================================
这一轮报来的四件事，其中两件是"看着像功能坏了、其实是界面没跟上"。
（0.2 的**干员 / 羁绊全量改版**那一大节，等到打 0.2 包时再补在这里。）

------------------------------------------------
一、★★ 修：炎羁绊的「燃烧」叠不上去、时长也不刷新
------------------------------------------------
表里写的是「每次攻击附着燃烧：每秒受到目标最大生命 1% 的法术伤害，
**最多 5 层**，每次被附着**刷新持续时间**（5 秒）」。
查下来是两处各自出问题，**都修了**：

1）**内核**（真 bug）：原来只有"已经满 5 层"那一条分支才会刷新时长，
   其余情况一律只新增一层。而最常见的节奏是"1 秒 1 刀 × 每层正好 5 秒" ——
   每次攻击之前刚好有一层到期，层数在 4↔5 之间来回，
   **那条刷新分支几乎永远执行不到**：早附着的那几层一直停在"还剩 1 跳"上。
   现在改成**每一刀都把身上所有燃烧层的时长刷满** ——
   语义正好是"这个减益一直被维持着，从最后一次附着算起 5 秒后才整体散掉"。
   （只刷时长、不动各层自己的跳动节奏，否则 5 层会在同一瞬间一起爆。）

2）**卡面**（看得见的那一半）：所有持续伤害在详情页里**按种类去重只留一条**，
   而留下的恰好是**最早那一层** ⇒ 5 层和 1 层长得一模一样，
   剩余时间还永远显示最小的那个（长期停在 0.2 秒）。
   现在燃烧单独成一类，显示成一条「🔥 燃烧 · 5 层 · 每跳 X 点 · 剩 5 秒」，
   剩余时间取**最长的那层**（也就是刚刷新过的那层）。

二、★ 修：陈的技能范围白框看着像"半径 3 格"
------------------------------------------------
陈·赤霄是「对**前方 3 格**所有敌人造成一次伤害」—— 内核一直是对的
（实测只有正前方那 3 格掉血，斜角和侧后方都打不到）。
不对的是**地上那个白框**：范围指示原来只会画"以目标为中心、半径 3 的方块"

三、★ 修：锏的刀光会被敌怪挡住

现在给刀光（刀身 + 命中爆闪）单独压了一层**高于所有棋子精灵**的渲染层级，
一定最后画、一定在最上面。
★ 位置（高度）一个数都没动 —— 这是图层问题，不是"特效飘得太低"。

一、★★ 断线重连之后，没装载的藏品不再消失
------------------------------------------------
以前你在藏品栏里攒着、还没装到干员身上的那些藏品，
一旦掉线重连（或者刷新一下页面）就**全部没了** —— 成长层数还在，东西不见了。

二、★★ 重开浏览器时，不再"什么都没发生"

页面刚打开时浏览器正在并发下载几百个素材，同一个进程忙不过来、那一次询问超时 ——
于是你既看不到「接管这一局」的提示、也不会自动回到对局，而且**一句话都不说**，
只能自己重新输房间号（多半早忘了）。

现在这次询问会**重试**，实在问不到就退回去读浏览器里那份记录，保证界面还有入口。
另外「加入房间」页面里新增了一颗**「断线重连恢复」**按钮：
它不依赖上面那次询问，随时点一下就能主动试着重连。

三、★ 队友掉线后，暂停倒计时不再卡在 3:00

暂停浮层上的倒计时以前是**不动的**（一直显示 3:00），看着像卡死了。

原因是两个数据源打架：真正每秒更新的是服务器推的"节拍"；

五、★ 领导人羁绊不再"显示生效、实际没用"

二、★★ 断线重连升级：令牌存进游戏进程
------------------------------------------------
以前令牌只存在**那一个标签页**里 —— 关掉标签页、甚至只是关掉浏览器，
令牌就没了，人也就回不到对局了。而"手滑关了浏览器"恰恰是最常见的掉线。

现在令牌由**你这台机器上的游戏进程**保管：

1）**关掉浏览器再打开，会自动回到原来那一局**
   （座位、血量、经济、阵容都在）。只要进程还在、座位还在
   （对局中 5 分钟宽限期内），重开就自动接上。

2）**一台机器只算一个玩家**。同一个进程开的第二个标签页不会再抢座位，
   而是弹一个提示「本机正在对局中」，你可以选：
     · 「接管这一局」——把对局接到这个标签页来
       （原来那个标签页会被顶下来，并明确提示它"被接管了"）；
     · 「留在菜单」——不动它，等另一个标签页自己关掉。

3）占用是靠**心跳**维持的：正在玩的那个标签页每 5 秒报一次到；
   20 秒没报到就当成"人走了"，别的标签页可以自动接管。

注意：这一条只在**局域网房间号**那种玩法下生效（页面由你自己的进程提供）。
如果你点的是别人发的隧道链接，页面来自对方那边、够不着自己的进程，
会自动退回老做法（只在同一个浏览器里有效，关掉浏览器就丢）。

0.1.3 测试版 追加（2026-10-14 晚）
================================================
按你实测报的 6 条改。前 5 条都是真 bug（其中 3 条是"同一个功能写了两遍、
只改了一处"留下的），第 6 条是平衡调整。

------------------------------------------------
一、★ 修：重开浏览器后点「接管这一局」没有任何反应
------------------------------------------------
**根因**：重连令牌是"这台机器的进程"保管的，里面记着它属于**哪一台服务器**；
而读令牌时会检查"地址和令牌记的那台对得上吗"。重开浏览器之后，连接地址会
回到**默认值**（当前页面主机:8787）——
· 房主那台：默认值恰好就是它自己，所以这条 bug 在他那儿看不出来；
· 客人那台：当初是用**房间号**找到房主的局域网地址连过去的
  （ws://192.168.x.x:8787），重开后默认值变回自己的 localhost:8787
  ⇒ 地址对不上 ⇒ 一个令牌都读不到 ⇒ `resume` 根本发不出去。
于是握手一切正常、界面也不报错，只是**没有任何人认领那个座位** ——
看起来就是"点了接管、然后什么都没有"。

现在「回到原来那一局」的第一步是**先把地址恢复成当初连的那台**，再谈重连
（房主路径、客人路径、"关掉浏览器再打开"的自动回座路径都走同一条）。

------------------------------------------------
二、★ 修：别人掉线到只剩房主时，房主被无限拖着打下去
------------------------------------------------
**根因**：掉线的人座位还留着（宽限期 5 分钟，方便重连），而服务器的"谁还活着"
里**包含了掉线的人** —— 于是剩下的人被一轮一轮拖着打：回合一直在推进、
掉线的人血掉得极慢，对局**永远不结束**（实测 30 秒推到第 33 回合还没有结算）。

现在按你说的做法：**人不够就暂停、等人回来**。
· 在线且活着的人少于 2 个 -> 冻结对局（不再开新回合，布阵倒计时也停住），
  顶部写明「等待其他玩家回来（还剩 xx 秒）」；
· 有人重连回来 -> 接着打（布阵打到一半被打断的，把剩下的秒数接着数完）；
· 宽限期到点、座位真的被清掉之后，只剩一个人 -> 判他赢、正常出结算页。

------------------------------------------------
三、★ 修：多人模式**战斗中买不了干员**（刷新、锁定、买经验却都可以）
------------------------------------------------
**根因**：联机买牌是**两条腿** —— 先问服务器，服务器同意之后再回到客户端落地。
"战斗中也能买"这条规则只加在了本地那条腿上，"+服务器已批准"这条腿还卡在
"只有布阵阶段能买"上。服务器其实已经把牌扣掉、金币也算好了，客户端却在这里
拒绝落地、把牌还回去、弹一句"战斗进行中不能购买"。
现在两条腿读**同一个判断**，不会再走散。

------------------------------------------------
四、★ 修：野怪回合看不到别人的战斗
------------------------------------------------
**根因**：野怪回合是"每个人各打一场自己 vs 同一波"，但四场战斗**共用一个编号**。
而客户端的观战列表按编号存 —— 每收到一场就把上一场覆盖掉，最后只剩一条，
"有 2 场以上才显示观战条"这个条件永远不成立。
现在每一场的编号带上玩家，观战条正常出现，随时可以切过去看别人打。

------------------------------------------------
五、新增：点一下房间号就能复制
------------------------------------------------
大厅里那 6 位房间号现在点一下就复制到剪贴板，直接粘给朋友
（复制成功/失败都会给一句提示；局域网 http 页面下 `navigator.clipboard`
不可用时会自动走老办法，不会假装成功）。

------------------------------------------------
六、调整：前 3 回合的布阵时间缩短到 30 秒
------------------------------------------------
开局那几回合每人手里就一两张牌，摆两下就完事了 —— 对着 60 秒倒计时干等没意义。
现在**第 1~3 回合布阵 30 秒，第 4 回合起恢复 60 秒**
（规则放在 shared 里，服务器真正等的秒数和界面上的文案读的是同一个函数）。

------------------------------------------------
七、顺手修：一批联机测试在 0.1.3 加"版本校验"之后就一直是红的

0.1.3 测试版 追加二（2026-10-14 夜）：卡面「技能条」
================================================

战斗里每张干员卡的**血条正下方**多了一条细的状态条（比血条细、和血条一样长、
底槽灰色），实时显示这个干员的技能情况：

--------------------------------
一、平时：蓝条 = 技能攒到多少了
--------------------------------
长度 = 法力 / 满蓝。满蓝就放技能、放完清零重新攒 —— 所以它同时也是
"下一个技能还有多久"的进度条。以前这条信息只在点开干员的面板里看得到，
现在扫一眼全场就知道谁快开技能了。

--------------------------------
二、技能开启时：按技能类型换样子（这是新增的部分）
--------------------------------
· **限时技能**（"接下来 10 秒攻击力 +X%"这类）-> 整条变**红色**，
  按剩余时间一格格退；
· **按次数的技能**（"接下来 5 次攻击攻击力 +1000%"这类）-> 整条变**橙色**，
  每攻击一次退一截（剩几次就显示几分之几）。

--------------------------------
三、没有这条的情况
--------------------------------
· **纯被动干员**（夜莺、星熊这种没有"要攒蓝才能放"的技能）—— 卡面上不画技能条；
· 同时有被动和主动技能的干员 —— 只表现**主动技能**那个窗口（被动不占位）；
· 已经阵亡 / 倒地等复活的 —— 状态条跟着人一起收起来。

--------------------------------
四、怎么做到的（一句话）
--------------------------------
"这个技能按时间还是按次数消耗"内核里本来就有一份权威说法（`duration.ts`：
数据写了 `attacks` 就是按次数、写了 `durationTicks` 就是按时间），
而"此刻还剩多少"内核也已经每 tick 采进属性时间线里了。
所以卡面只是把这两样读出来除一下 —— **一行战斗逻辑都没改**，
确定性与校验和自然一个字都不动（联机不受影响）。

新增测试 11 条（`apps/web/test/skill-bar.test.ts`）：纯被动不画条、蓝条 = 攒蓝进度、
限时技能变红条且按剩余时间退、按次数技能变橙条且按剩余次数退、
别的效果（眩晕/护盾/免疫）不许把条染色、三种模式颜色各不相同且底槽是灰的，
外加一条**真打一场**的用例：技能生效中的棋子卡面确实亮出了红条、
纯被动棋子的卡面从头到尾没亮过。

★ 配色调整（同日晚）：第一版用的是亮蓝/亮红/亮橙，在只有 9px 高的细条上
被白色高光一冲就发白，远看和血条糊在一起。改成**更深的深蓝 / 正红 / 深橙**
（高光也跟着减弱一半），几像素高也能一眼分清是哪种状态；
顺带把底槽的灰也加深一点，和填充的对比更清楚。

0.1.3 测试版 追加三（2026-10-14 深夜）
================================================
这一轮 3 个 bug + 1 个新入口，都跟"人中途掉线"和"开战那一瞬间"有关。

------------------------------------------------
一、★ 修：藏品拖在鼠标上时开战，藏品会凭空消失
------------------------------------------------
**根因**：拖动藏品时，那件藏品是"贴在鼠标上的"（暂时不在任何栏位里）。
开战的收尾动作会按"栏位里现在有什么"重建一次藏品栏 ——
贴着鼠标的那件不在任何栏位里，就被当成"已经没人要了"清掉了。

现在开战前先把这次拖动**取消掉**：藏品自己回到原来那个栏位（人还在场上就随身带着走），
不会丢。取消动作走的是和其他地方同一个"收手"入口，不会产生第二套逻辑。

------------------------------------------------
二、★ 修：掉线重连"有时候能回、有时候回不去（大概率回不去）"
------------------------------------------------
**根因**：新建连接时，服务器会先发一条"欢迎"消息，里面带的是**这条连接的临时令牌**；
客户端紧接着拿真正的令牌去重连，服务器认下身份之后会把那枚临时令牌**作废**。
问题在于客户端有时候把"临时那枚"当成自己的凭据存了下来 ——
下一次重连拿着一枚已经作废的令牌去敲门，服务器只回一句"凭据无效"，
界面上没有任何提示，看起来就是"点了没反应 / 回不去"。
（这也解释了为什么"有时候能回"：只有临时令牌恰好没被换掉的那几次才成功。）

现在两处一起改：
· 服务器重连成功之后**补发一条带正确令牌的欢迎消息**（顺序在房间广播之前，
  免得客户端先把错的那个写进本机会话）；
· 客户端"这一条连接已经发过重连请求"期间，不再用欢迎消息里的令牌覆盖自己的。
连着断两次也能每次都拿最初那枚令牌回去（已加测试钉住）。

------------------------------------------------
三、★★ 暂停规则重做：只要有人掉线就暂停，可以投票提前结束
------------------------------------------------
上一版是"在线的人少于 2 个才暂停" —— 4 人局里掉一个，剩下 3 个人还得干等，
而且倒计时只有 30 秒、结束就判剩下的赢，掉线的人常常是被"顺手清掉"的。

现在的规则（按你说的来）：

1）**只要还有一个活着的玩家掉线，立刻暂停**（不再等到只剩一个人）。
   顶部写明「等待其他玩家回来（还剩 x:xx）」，棋盘照旧可以摆、可以看别人阵容 ——
   浮层不挡操作，只是盖一层提示。

2）**等 3 分钟**（原来 30 秒）。

3）**暂停途中又有人掉线 -> 倒计时从头开始**，已经投的票也一并作废重投
   （不然人越掉越少、时间越剩越少，最后一个回来的人反而被秒淘汰）。

4）**所有人可以投票提前取消暂停**：每个人（掉线的人不算）都能看到同一个浮层，
   上面只有一个「同意」按钮 —— 点完变成「已同意（等其他人）」；
   **所有人都点了同意，暂停立刻取消**，掉线的那位**当场淘汰**，剩下的人接着打。

5）**3 分钟到点还没回来 -> 掉线的人淘汰**，对局继续（只剩一个人就正常出结算页）。

------------------------------------------------
四、新增：主界面右下角「回到对局」
------------------------------------------------
主界面右下角多了一个「回到对局」按钮（带一个呼吸的小圆点）：
· 本机有正在进行的对局 -> 显示，点一下自动接回去
  （会先把服务器地址恢复成当初连的那台，和自动回座走同一条路）；
· 本机已经有人在玩（另一个标签页占着）-> 不硬抢，弹「接管这一局」问一句；
· 本机什么都没有 -> 按钮不出现，不占地方。

------------------------------------------------
五、这一轮加的测试
------------------------------------------------
· 服务端：掉线即暂停、3 分钟到点淘汰、全员同意立刻取消并当场淘汰、暂停途中再掉线重新计时 —— 5 条
· 服务端：连断两次都带最初那枚令牌（第二次不许是临时令牌）—— 1 条
· 界面：暂停浮层的倒计时/同意进度/文案、点同意真发投票、票被清零后能重投、暂停结束浮层收起 —— 2 条
· 界面：主界面「回到对局」的显隐与"不硬抢" —— 3 条
· 界面：藏品拖在鼠标上开战 -> 回到栏位不丢失 —— 1 条

测试版追加内容（2026-10-13）
================================================
这一轮加了三件事：**断线重连**、**战斗中也能买卖棋子**、**测试模式的数值修改**；
另外把观战窗口整个放开，并修掉几个界面上的老毛病。

------------------------------------------------
一、★★ 断线重连（新功能）
------------------------------------------------
以前"连接一断就等于退房"——人还在，座位已经没了，重开就是一局新的。
现在**掉线不等于退房**：

1）座位、血量、经济、阵容、牌库都**原地留着**，等你回来。
   等待时间：大厅里 30 秒、对局中 5 分钟（够你切个 WiFi、拔插一下网线、
   手机信号抖一下再回来）。到点还没回来，座位才真的清掉。

2）**不用做任何操作**：游戏会自动重连。它手里有一张"回座位的凭据"，
   连上之后拿它换回**原来那个身份**——所以你的血量、连胜、商店里的牌
   都还是原来那一份（商店的随机序列也不会重排）。

3）**刷新页面也回得来**。手滑按了 F5、或者浏览器崩了重新打开，
   只要还在这一局里，回来就是原来的局面（棋盘、备战席、身上的藏品、
   金币都会照服务器那份装回来）。

4）**离开期间错过的会一次补齐**：
   · 房间里现在什么阶段、还剩几秒布阵；
   · 牌库剩几张、谁占着哪几张；
   · 别人摆了什么阵容；
   · ★ 如果这一回合正在打，会把你那一场**从该接上的那一秒**继续播
     （不会从第 0 秒重播，也不会直接跳到结果）。

5）掉线期间**不占"等其他人看完"的名额** —— 不然全房间要陪你干等一两分钟。

6）房主掉线会自动把房主交给还在线的人，房间不会挂着一位离线房主。

7）★ **同一个身份在两处进入**（同一浏览器开了两个标签页、手机和电脑同时开着）：
   后到的那个顶掉先到的，先到的那边会明确告诉你"你在另一处进入了游戏"并退出。
   不会出现两边无限互踢、或者两个人共用一个座位互相覆盖。

8）界面上：重连期间会盖一层「正在重连…」（带一个「立即重试」按钮）。
   如果你确认网络已经好了，点它就不用等自动重试的间隔。
   真的回不去时（服务器重启过 / 房间散了），会干脆地回主界面并说清原因。

------------------------------------------------
二、★ 战斗中也能买卖棋子 / 刷新 / 锁定商店
------------------------------------------------
以前只有布阵阶段能操作商店，一开打整条商店就锁死了 ——
手里一堆钱花不出去，只能干看着。

现在：
· **战斗演出期间**、以及**打完之后等别人看完**的那段时间，商店整条都能用
  （买、卖、刷新、锁定、买经验）。
· 仍然只在布阵阶段有效的只有一件事：**改上场阵容**（开打了就不能再动棋子）。
· 对局真正结束时会弹全屏结算页盖住界面，不会让你误操作。

------------------------------------------------
三、★★ 观战窗口放开
------------------------------------------------
· **自己那场打完之后还能接着看别人的战斗**（以前一打完就再也点不开了）。
  从"我打完了"到"进入下一回合布阵"之前，随时可以切过去看。
· **野怪回合也能观战**。
· 期间不会再被莫名拽回自己那一场，也不会拿别人的战果弹你自己的结算横幅。

------------------------------------------------
四、★ 测试模式：修改器新增「数值修改」
------------------------------------------------
打开修改器里的「数值修改」之后，布阵阶段点场上的干员**不再弹详情页**，
改弹一个「基础属性」面板，可以直接改：

    生命 / 攻击 / 攻速 / 护甲 / 魔抗 / 射程

· 改的是**这一张卡**，不是这一种干员 —— 同名干员的另一张不受影响。
· 只在本局生效，随时可以「恢复白板」还原成数据表里的原值。
· 改的是**基础属性**，羁绊 / 藏品的加成照旧叠在上面
  （所以改完 4500 生命、吃到羁绊会显示得更高，这是对的）。
· 保存之后开打，用的就是你填的数值（真打，不是只改界面）。
· 填了非法值（0 血、空的、字母）会**报错并拦住**，不会悄悄改成别的数。

------------------------------------------------
五、修掉的问题
------------------------------------------------
· ★ **测试模式改完干员数值后"数值会自己复原"** —— 修好了。两个原因：
  ① 面板判"这一项改过没"时拿错了基准（用的是**改过之后的当前值**，不是数据表原值）。
     于是改完 8888 再打开面板、什么都不动、按一次保存 —— 它以为"你填的就是原值"，
     把这条覆盖删掉了，数值当场退回白板。现在基准统一用数据表原值，
     输入框上的 tooltip 也是真的原值、行上的"已改过"标记也能正确显示了。
  ② 点面板**外面**（包括「切换到红方」按钮）会把面板直接收掉，
     刚填还没按保存的数字就丢了。现在改成**先落盘再收起**；
     真要撤销请按面板上的 ✕ / 取消。填了非法值时不会切阵营，留在原地报错。
· ★ **战斗打完之后回合不推进（单机 / 测试模式都中招）** —— 修好了。
  根因：上一轮修"旁观别人的战斗会被算成自己的战果"时加了一条"必须正在看
  **自己那一场**才允许收尾"；但"我在看哪一场"这个变量**只有联机**才会被赋值，
  单机 / 测试沙盒里恒为空 —— 于是**永远收不了尾**：战斗播完画面停在战斗阶段、
  回合号一直不动。现在把口径抽成纯函数 `shouldFinishBattle`（联机按"是不是自己那场"
  判，单机直接算自己那场），并配了单元测试 + 一条"真开一局等它打完"的端到端测试。
· ★ **多人模式观战结束后，日志会显示成别人的战斗** —— 修好了。
  根因有三个：点开别人的战斗时会把"当前阶段"改错（于是立刻被拽回自己那场）、
  "该回去收尾了"的判断少了一道阶段闸门、以及回放循环在结算阶段不推进
  （旁观别人时画面会定住）。现在三条都堵上了。
· ★ **3 星棋子详情页里的 ▲▼ 一直是错的** —— 修好了。
  以前界面自己算"白板值"时漏了 3 星质变那部分加血，所以基准偏低一截，
  于是每个数值都显示"涨了"。现在和开战用的是同一份算法。
· 联机里"掉线就直接退房"（见第一节）。
· 房主掉线后房间没人能开局、也没人能踢人（现在会自动换房主）。

------------------------------------------------
二、★ 藏品系统：成长、效果栏、实时数值
------------------------------------------------
1）**跨回合成长**
   这批藏品有的按"击倒了几个人"涨、有的按"赢了几场"涨、有的按回合数涨、

· **骑士长枪专业版（野怪回合金币 +50%）以前完全没有生效** —— 数据里写了、

· ★ **"随机效果每回合结果都一样"** —— 修好了。以前单机（含测试沙盒）的战斗种子

------------------------------------------------
七、怎么开始
------------------------------------------------
1. 解压整个文件夹（别只拖单个文件出来）。
2. 双击「启动游戏.cmd」，浏览器会自动打开游戏。
3. 想和朋友一起玩：
   · **朋友也双击他自己那份「启动游戏.cmd」**，然后在游戏里点「加入房间」，
     把你报给他的 **6 位房间号**填进去就行 —— 同一个 WiFi 会自动找到你。
   · 朋友没有这份游戏（或者不在同一个网络）时，才需要把黑色窗口里打印的那条链接
     发给他（**一定要带上 ?server=... 那一截**），他直接点开就能进。
4. 第一次运行 Windows 可能弹「防火墙」提示，点「允许访问」，不然同一 WiFi 的朋友连不上。
5. 本包自带 62 首背景音乐（左上角音乐按钮可以开关）。
